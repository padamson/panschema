## [Unreleased]

### Changed
- **The `rules` silent-drop warning names where the constraint lives.** A format that does not project class `rules` (the RDF/OWL family among them) still warns per class, and the line now points at the `shacl` output as the constraint-bearing projection. Keeping rules out of the ontology graph is deliberate — OWL has no native construct for conditional rules — and a consumer wanting one self-describing graph can union the ontology with the emitted shapes, which one manifest entry can produce side by side.
- **A LinkML YAML schema that omits `default_range` now means `default_range: string`, as LinkML's derivation rules specify.** Previously the omission left slots untyped, and each output chose its own meaning for that (the JSON Schema projection typed them `string`, everything else emitted nothing). The implicit default is applied per file at read time — in a multi-file schema, an imported file that omits it gets its own implicit `string`, never the importing schema's declared default, the same scoping a declared default has always had. Derivation order is ancestors first, default last: a specializing slot still inherits its parent chain's range, wherever the parent is declared, and only a chain that yields nothing falls back to the default. An `any_of` whose branches carry only facets (patterns, bounds) constrains values it never types, so a default — declared or implicit — now fills its range too; branches that carry ranges keep the default out. This applies to LinkML YAML sources only — an OWL/Turtle property without `rdfs:range` is genuinely rangeless and keeps the untyped-slot warning below. **Note:** data that previously validated clean may now fail — a wrong-kinded value at a previously-untyped slot was a silent pass and is now a `string` kind violation, and RDF, SHACL, Postgres, and HTML now project these slots as `string` where they emitted nothing.

- **A null under a class-ranged slot is now a reported kind mismatch, not a silently absent value.** A null can never reference a record, and dropping it silently shortened authored reference lists. `validate` now warns on it like any other wrong-kinded value, and a stated absence claim carrying one is uncheckable rather than quietly narrowed. A null at a scalar-ranged slot keeps meaning absent.

### Added
- **A versioned publish can document a dependency schema beside its own — the contract-plus-local-records page.** An `[[instances]]` entry naming a dependency from the repo's manifest (`schema = "<dep>"`) moves its dataset onto a second published page that renders the dependency's schema with the data embedded; entries naming the same dependency share one page. The page lives in its own directory inside the publish output tree (`[publishing.pages.<dep>] dir = "..."`, defaulting to the dependency's name), versioned and aliased like the main page, and takes the same composition options per page (`layout`, `schema_sections`). It exists only at refs where the dependency resolves and some of its data is present: the version dropdown offers exactly those refs, and when the configured `current` isn't among them the page publishes without a `current/` alias — said out loud, with any stale alias from a previous run into the same tree removed, and the page's banner and brand link treating its newest released ref as current. Each ref renders its own data against the dependency version that ref's manifest pins, resolved from the local cache only — publish never fetches over the network, and a cold cache skips the page with a note naming `panschema fetch` as the fix — while `path:` dependencies, which carry no pin, resolve from the working tree. The dataset's cross-graph references draw as the external nodes the instance graph uses everywhere. Naming a dependency the manifest doesn't declare fails the publish naming the entry and the missing dependency; so does a page directory that isn't a fresh single path segment — escaping the tree, colliding with a version label or another page, or claiming the reserved `current` — and version labels themselves now pass the same segment rule.
- **Published pages choose their composition.** An HTML schema-docs page can lead with the instance graph instead of the schema reference (`layout = "instances-first"` under `[publishing]`, or `html_page_layout` in a manifest's `[generate.<name>]` table), and can omit the schema reference sections — the schema graph and the class/slot/enumeration/type cards — entirely (`schema_sections = false` / `html_schema_sections = false`), leaving a page built around its data — the metadata card and namespace table stay, the instance cards keep their labels without dead links into the omitted sections, and a page that would render empty warns. The sidebar follows the page's order and sections, defaults reproduce today's page byte for byte, and an unknown layout value fails at parse naming the accepted ones — as does an unknown key under `[publishing]`, which previously reverted to its default silently.
- **LinkML's `designates_type` chooses a union member outright.** A slot marked `designates_type: true` names its record's class — by name, IRI, or CURIE — and at an `any_of` union of classes that authored answer now decides which member an inline record builds as, outranking the field-name heuristic. Every member's designator key is consulted: a conflict between two designators, a non-string value, or a value naming nothing on a key every member treats as a designator leaves the record a reported unusable entry rather than a guess, while a key that is an ordinary slot for the record's true member stays plain data. `slot_usage` overrides carry the marker, and a designator no longer counts against a class's one open SimpleDict slot. Schemas declaring a designator on every union member — the spec-conformant shape the heuristic alone read as ambiguous — load exactly as authored. A union member can also be chosen by naming its subclass: a value that is no member's own name resolves against the `is_a` families of the members whose own designator the key is — and only when no member reads that key as plain data, so a data value coinciding with another member's subclass name can never hijack the record. The one member whose family holds the named class is chosen and the record builds as that subclass; a value reaching into several such families (nested members) stays a reported conflict, and an ambiguity among one member's own subclasses — a shared `class_uri` — still loads the record as that member, exactly as a single-class range would, leaving the value to conformance. The canonical single-class use is modeled too: at a single class range, a designator value naming a *subclass* of the declared range (through the class's `is_a` chain, by name, IRI, or CURIE) types the record as that subclass, so its own fields are declared fields and every projection sees the class the data named; an unresolvable value leaves the declared range standing rather than refusing the record. `validate` now checks agreement: a designator value that does not name the record's own class — or is not a string — is a reported violation, instead of shipping a graph whose `rdf:type` and designator contradict each other. The Rust projection dispatches on it through a generated deserializer, never serde's own tag machinery (which would reject spellings the loader accepts): the designator value is peeked — never consumed, so the variant struct keeps its own field and the wire carries the key once — and resolved through a table compiled from the schema and kept in lockstep with the loader's matcher by an equivalence test: each class's name, IRI, every CURIE the schema's prefixes can form, and the bare local name the default prefix expands, with subclasses answering for their union member and `is_a` alone deciding descent, exactly as the loader walks it. An absent designator falls back to shape, the untagged rule; an unresolvable or non-string one errors at a union, where the loader refuses, and falls back to shape on a subclass enum, where the loader keeps the declared class. Generated modules with a designated enum list `serde_json` among their requirements, since the deserializer buffers through it — a documented trade: non-JSON data models degrade (a YAML `NaN` reads as null). A union member with subclasses carries its `<Name>Kind` enum, so a subclass designation dispatches through both layers into the concrete class, its own fields kept; the shape fallback, wherever it runs, takes the first variant that fits in declaration order. And an absence claim's `via` narrowing resolves through the same name-or-IRI matcher a designator uses, so a bare class name narrows the claim where previously only an IRI or CURIE did — an IRI several sibling classes share is reported uncheckable, a narrowing having to name one thing.
- **Bare `panschema validate` checks the whole manifest, and validation policy lives in `[check.<name>]`.** Checking previously required generating: the cross-graph keys sat under `[generate.<name>]` and ran only when an output writer ingested the instance data, so a manifest wanting only the gate had to declare an artifact for the side effect, and `validate` — flag-driven, manifest-blind — covered less than `generate --strict`. `validate` with no flags now reads `panschema.toml` and checks everything it declares, writing nothing: instance conformance for every dataset, cross-graph resolution, and stated absences, with findings as warnings and `--strict` promoting them — the same split as `cargo check` against `cargo build`, with `generate --strict` still refusing to ship what the checks reject for entries it generates. Bare `validate --strict` also promotes the schema-level diagnostics `generate --strict` refuses — untyped slots, dangling schema references — and reports every entry's findings before failing once, so fixing proceeds from one complete report. The `resolve_against` and `verify_absences` keys move to `[check.<name>]`, whose own `instances` list unions with the generate entry's (it can add datasets, never hide shipped ones), and which gains an opt-in `require_namespace_coverage`: every external reference must land in a namespace some `resolve_against` sibling owns, so a typo'd namespace can no longer pass as an outside vocabulary. The old key placement is a parse error, and a `[check.<name>]` naming no `[schemas]` entry is a configuration error — neither is a silent no-op.
- **`verify_absences` checks a dataset's stated absence claims against the `resolve_against` siblings.** A claim of the form "no record joins these anchors" had no generic check — its truth lives in the graph under evaluation, not in the claiming file. The key binds the claim to the schema's own slots (`verify_absences = { slot = "...", via = "..." }`): a record listing anchors under the bound slot (reference targets or IRI-valued scalars) claims no single sibling record references them all — a single anchor claims no record references it at all. A "reference" is an authored object-reference edge; a sibling citing an anchor's IRI in a plain scalar is not counted. `via` optionally narrows the claim to joining records of one class, named by IRI or CURIE. Holding is not joining, at any depth: a container's collection slots and any edge that materialized an inlined child are containment, not citation — restating an already-declared record inline is a citation — and a root-class record that isn't the container still counts. A claim the check cannot evaluate — a null or malformed anchor or `via` value, several `via` values, anchors collapsing to fewer distinct IRIs than authored, an anchor no sibling mints, a `via` naming no class any sibling declares — is reported as uncheckable, never as holding: evaluating what remains would silently strengthen the claim. A narrowed claim's contradiction names the narrowing. Contradicted and uncheckable claims warn with their specifics, a note counts how many claims hold, and `--strict` fails on either. The binding lives in the manifest deliberately: the schema states the domain semantics in its own terms and stays free of tool annotations, so it means the same thing to every consumer in every projection. Binding a slot no class carries is a configuration error.
- **`resolve_against` on a `[check.<name>]` entry checks that a dataset's cross-graph references actually resolve into sibling entries' datasets.** A dataset whose references leave it by design — a benchmark whose anchors name records of the graph it evaluates — passes the dangling check with its external references summarized as "not checked here". When the referenced graphs live in the same manifest, this key (an array of entry names) closes the loop: every external reference landing in a namespace a listed sibling owns must equal an IRI that sibling's datasets mint — expanded against the referring schema exactly as RDF emission expands it, and computed by the sibling schema's own minting rules, so a `key`-scoped record's dataset-rooted IRI is what a reference must match, where a hand-rolled `namespace + bare id` lookup silently resolves the wrong thing. References into namespaces no sibling owns stay unchecked, so a dataset can still cite outside vocabularies without failing the run. Unresolved references warn, naming the record, slot, reference, and expected IRI; a note counts how many in-scope references resolve either way; `--strict` fails the run on any unresolved one. Naming the entry itself or a name with no `[schemas]` entry is a configuration error; a sibling with no datasets yet is not — the run says why nothing can resolve and proceeds. The check runs before any writer and writes nothing; bare `validate` runs it without generating at all. Alongside it, a `urn:` reference is now classified as leaving the dataset like any other absolute IRI, instead of failing the dangling check as a bare id.
- **A slot left untyped at load is now reported, and `--strict` refuses it.** With the implicit default above, a LinkML YAML slot is typed unless nothing can reach it — so what remains untyped is an OWL/Turtle property without `rdfs:range`, or a slot a class introduces only through `slot_usage`, which no default can fill. For those, every output makes its own choice about what untyped means: the JSON Schema projection types them as `string` while RDF, SHACL, Postgres, HTML, and `validate` leave them unconstrained — the same slot rejects `42` in one output and accepts it everywhere else. The check reads the *resolved* view, so a top-level slot every consumer ranges through `slot_usage` is not reported, and the warning names each slot's definition site and the ways out: a `range:` or `slot_usage` range in YAML, `rdfs:range` in OWL/Turtle, or a `default_range`.

### Fixed
- **A union over a subclassed class — or a scalar — generates valid Rust.** An `any_of` member that is itself an `is_a` parent (or mixin target) renders as a trait with no struct, yet the union enum typed its variant `Box<Member>` — naming the trait as a type, so the generated module failed to compile; a member ranging over a primitive, a time type, or a custom `types:` entry failed the same way. Union variants now take exactly the type a field with that range takes, through the one shared mapping: a subclassed member carries its closed `<Name>Kind` enum (sized, unboxed — it boxes internally), scalars are plain values, and only class payloads box. A parent or intermediate class itself remains uninstantiable in the Rust projection, and a designator naming one is refused with an error saying so — never silently retyped into whichever subclass shape fits first; a member with no concrete descendant at all has no variant, its designations refused the same way.
- **A rule's equals condition on a multivalued slot now tests membership, so a second value can no longer silently disable the rule.** `equals_string`/`equals_number` previously demanded every value equal the constant, so a precondition like "when `answer_kind` includes `closed-world-negative`" stopped firing the moment a record carried a second kind — the record that most needed checking was exactly the one that escaped, silently. The condition now holds when at least one value equals, matching the `sh:hasValue` the SHACL projection emits for the same condition, so the native validator and the generated shapes agree on when a rule fires; a single-valued slot behaves as before. The same reading applies to postconditions (the required value present among others conforms), and an equals condition on an absent slot is now unmet rather than vacuously met — "when status is actual" cannot hold for a record with no status. **Note:** the change cuts both ways — data that previously validated clean may now fail where a multivalued precondition was being silently skipped, and data that previously failed may now pass where a rule fired vacuously on a record whose gating slot was absent, or held only references (which never equal a literal constant).
- **Generated instance-data literals are typed by the slot's declared range, so conforming data can no longer contradict the SHACL shapes emitted from the same schema.** Literal datatypes previously followed the value's parse kind: a date at a `date`-ranged slot emitted as `xsd:string`, an integer under a `decimal` range as `xsd:double` — while the same run's shapes constrained those properties to `sh:datatype xsd:date` / `xsd:decimal`, so well-formed data generated RDF that failed its own shapes. A conforming value now takes the datatype the shapes constrain it to, derived from the same table, with its lexical form canonicalized for that datatype (an integral float under `integer` spells `"5"`, never the ill-formed `"5.0"^^xsd:integer`; non-finite floats take XSD's `NaN`/`INF` spellings). A rule's `equals_string`/`equals_number` constants project through the same derivation, since `sh:hasValue` is datatype-sensitive term equality and a differently-typed constant could never match conforming data. A value the range cannot faithfully type — a wrong-kinded value, a malformed date, `NaN` under `decimal`, a magnitude beyond `xsd:float`'s single-precision value space — still emits, as authored with its own value-kind typing: nothing vanishes from the output, the literal stays well-formed, and the mismatch is visible to the shapes and reported by the conformance check that runs on the way into every output. Ranges the shapes leave unconstrained (no range and no `default_range`, custom types, enum and class ranges) keep their existing behavior. One deliberate datatype change rides along: a `float`-ranged slot's values now emit as `xsd:float` rather than `xsd:double`, matching the shapes; SPARQL numeric promotion still joins them against other numeric types.
- **A cross-graph reference on the dataset container's own slots is no longer reported as dangling.** References that point outside the dataset — absolute IRIs, or CURIEs against a declared prefix — are exempt from the dangling-reference check by design and summarized as unchecked cross-graph edges instead. That exemption applied to references held by ordinary records but not to those on the `tree_root` container itself, so a dataset whose root records IRIs into another graph — the shape of a retrieval benchmark, whose anchors name nodes in the graph under evaluation, never in the benchmark file — failed validation with one error per IRI. Such references now take the same external classification as everywhere else: exempt from the dangling check, named in the cross-graph summary, and still subject to the slot-specialization containment check, which compares the values themselves and needs no local record. A bare id on a container slot remains an intra-dataset promise and is still dangling-checked.
- **A single-valued class-ranged slot on the dataset container now loads its record.** Such a slot was treated as a collection: an inline record was misread as an identifier-keyed dictionary — minting one phantom record per field, named after the field, while the intended record was never built — and a bare id was dropped entirely, so the container's citation vanished from every output. The slot now loads like any record's single-valued reference slot: an inline mapping materializes the one record it holds (a containment edge), and a bare id cites an existing record. The phantom records could falsely contradict a stated absence claim under `--strict`, naming a joiner that appears nowhere in the data.
- **A union of class ranges now loads inline records and container collections instead of dropping them.** A class-ranged container slot expressed through `any_of` read only the declared scalar range, which a union leaves empty, so the collection's records vanished without a trace. And an inline mapping at any union of classes — on a container slot or an ordinary record's, including unions mixing classes with types — was recorded as an unusable value: never materialized, its content lost to every projection, and invisible to absence verification, so a claim it contradicted could report as holding. Container slots now resolve their range targets through the same induced view record building uses, and an inline mapping builds as the union member its type designator names or, absent one, the member matching the most of its authored keys — repeated branches naming one class are one candidate, an unknown field is the usual named undeclared-field diagnostic rather than a forfeit, and a mapping that fits several members equally (or none at all) is still reported as unusable, never built by guessing. This holds whether or not the dataset emits a container record, and for every spelling of a container collection: an identifier-keyed dict (or compact SimpleDict) at a union of classes loads entry by entry, each choosing its member independently — a compact scalar entry by the one member with a single open slot to fill — where previously only the list spelling loaded and the dict form vanished whole. A collection entry that loads no record is now a reported validation finding naming the entry and why — a mapping whose fields choose no single member, a compact entry several members could fill, a null, a non-string key, or a dict key that matches a member's own field name (an un-wrapped record, which would otherwise mint a phantom named after the field) — even when no container record exists to carry it. Numbers and booleans among collection entries are reported the same way rather than minting citations of records named `5` or `true`, for single-class collections too. Collection entries are containment edges by role in every spelling, so a container merely listing an anchor's id does not contradict a stated absence claim about it; a union mixing several classes with scalar types keeps record-level rules, where a bare string stays a literal. A mapping that still names no member is reported as such — validation now says its fields name none of the slot's class ranges and to add a field only the intended one declares, rather than calling an object invalid for a class range. All of this holds at any nesting depth, not only on the container: a record's own multivalued class-ranged slot previously misread an identifier-keyed dict as one inline record — collapsing a union's collection into a single unusable-value report, and at a single class minting one phantom record, each entry reported as an undeclared field, while the real records vanished — a fabricated record that could falsely contradict a stated absence claim. Such a mapping now walks entry by entry under the container's rules, with one record-level distinction kept: restating an already-materialized record stays a citation, as the inline and list spellings at that depth already read it. Effective cardinality decides which slots take a collection everywhere, so `maximum_cardinality` of two or more admits the dict spellings without a `multivalued` flag and `maximum_cardinality: 1` keeps a flagged slot single-valued. One consequence cuts the other way: an un-wrapped inline record at a multivalued class-ranged slot (`held: {id: x}` rather than `held: [{id: x}]`) — whether the range is a single class or a union whose fields chose one member — previously built as the collection's one element and is now the same reported finding the container gives, asking for the record to be wrapped in a list rather than building from a guess. And wherever a mapping is about to build as one record — a collection entry, a dict entry's value, a single-valued slot, at either depth — one that only reads as an identifier-keyed dict of records (two or more entries, none keyed by any field of the range, records among the values) is a reported finding telling the author to give each record its own entry, where it previously minted one phantom record named after nothing the data authored while the real records vanished behind it. A single unknown object-valued field stays what it always was: a record with a typo'd or extension field, built and reported by name. And every unusable-entry finding below the container now names the record whose slot holds it, so a defective entry can be located in data with many records.
- **A container that never authors its declared identifier no longer fabricates one.** The emission gate was schema-level, so data omitting the identifier value emitted a phantom container under a synthesized id that shifted with the instance count — and every key-scoped record's IRI shifted with it. Such a dataset now loads vessel-rooted: its records exist, no container is emitted, and nothing depends on a fabricated id.
- **A non-string field key is a reported finding, not a silent drop — and the container keeps undeclared fields like any record.** An unquoted YAML key like `2024:` or `true:` parses as a number or boolean, can name no slot, and its value was discarded without a trace — on records, on the dataset container, and as an identifier-keyed collection entry's key. It is now reported against the right record identity with advice that fits (quote a number or boolean; a mapping, sequence, or null key has nothing to quote), one finding per authored defect however many times a record is restated. An undeclared *string* field on the container, previously dropped silently while records kept theirs, is now kept and reported the same way.
- **A dataset container whose id collides with a record's is reported, not silently merged.** The container record is built after the records it holds, so when its id was already taken the loader attached the container's collection edges to that ordinary record and treated it as the container — wrong edges in every projection, and the collision never surfaced. The collision is now a reported duplicate identifier that names its consequence — no container is emitted, and key-scoped records mint unscoped until it is resolved — and `generate` refuses to resolve references or verify absences against a sibling dataset in that state rather than reporting authoritative results off a degraded graph. The same discipline applies below the container: restating an existing record's id with different content — a different class, or values the kept record does not carry — is a reported duplicate instead of a silent discard, while an identical restatement remains what it always was, one entity referenced two ways.

## [0.3.1] - 2026-08-13

### Added
- **The `mdbook-panschema` binary ships with the `panschema` crate.** One `cargo install panschema` now provides both tools; the separate crate is retired. Its only tie to panschema was reusing the `[book_link]` config types — for which it compiled the entire library — and its audience (repos publishing panschema-generated schema docs) installs panschema anyway. The binary name — which the planned preprocessor role requires, since mdbook discovers a preprocessor by invoking `mdbook-<name>` — and the idiomatic `mdbook-panschema install` verb are unchanged, and release archives carry both binaries.

## [0.3.0] - 2026-08-13

### Added
- **`generate --check`: the committed-codegen drift gate, natively.** Consumers that commit generated outputs each hand-rolled the same CI gate — run `generate`, then `git diff` the output directory, with all of git's edge cases (uncommitted changes look like drift, a baseline is required). `--check` regenerates to a temporary location, byte-compares against every output the manifest declares, exits non-zero naming each drifted or missing file, and writes nothing. HTML outputs are directories and are skipped with an explicit warning rather than silently. The generated Rust header now also names the consumer's exact `Cargo.toml` requirements — including the time crate's `serde` feature, whose absence otherwise fails the build with missing-impl errors that don't say why.
- **The generated Rust module's time crate is selectable per consumer.** `rust_time = "jiff"` beside the manifest's `rust` output key maps temporal ranges to `jiff::Timestamp` / `jiff::civil::Date` / `jiff::civil::Time` instead of the chrono defaults, for workspaces that deliberately carry jiff rather than chrono. The wire format is unchanged either way — RFC 3339 / ISO 8601 strings through serde, trailing-Z timestamps, proven by a downstream-crate round-trip — and an unsupported value fails the run rather than silently falling back. `Default` derives gate identically under both crates, so switching never changes the generated API shape beyond the field types.
- **The OWL reader says what it drops.** Reading is a projection, and some inputs carry more than the internal model holds: a property with several `rdfs:subPropertyOf` axioms keeps one parent (LinkML's `is_a` is single-valued), and a parent the ontology doesn't define — a `dcterms:` term, an OWL builtin — cannot be represented at all. Both previously vanished without a word; every command that loads a Turtle schema now prints a warning naming the property, what was kept, and what was dropped. The reader interface gained a warnings channel (`read_with_warnings`) so other readers can report their own lossy projections the same way.
- **Slot-level `is_a` is modelled: a slot can specialize another, and every projection either states the relation or states that it can't.** LinkML's `is_a:` on a slot declares that every value of the child is also a value of the parent — previously parsed as an unknown key with no effect anywhere. RDF/OWL output emits `rdfs:subPropertyOf`, and the OWL reader maps the axiom back for parents the ontology itself defines — an external parent (a `dcterms:` term, an OWL builtin) is left unmapped rather than rewritten into the local namespace, and several axioms project deterministically onto the single-valued field. The HTML slot card shows "Specializes: <parent>", and `validate` enforces the subset on instance data with the same number semantics as its kind check — a child-slot value missing from the parent slot's values on the same record is a violation, since no reasoner runs on the YAML path and RDFS entailment would silently widen the parent set instead of erroring. Where the relation can't land, that is said out loud: an `is_a` naming no known slot (including inside `slot_usage`) is a dangling-reference warning, a class using the child slot without its parent is warned that the subset goes unchecked there, and every writer whose format has no sub-property form — SHACL (Core has no subset constraint), JSON Schema, Rust, Postgres, and graph JSON — reports the drop as a projection gap rather than making it silently. A `slot_usage`-declared `is_a` is class-scoped: `validate` enforces it for that class's records, and no global RDF axiom is emitted for it. A specializing slot inherits its parent chain's unset metaslots at load time — `range`, `description`, `pattern`, numeric bounds, cardinalities, and the other option-valued fields, nearest ancestor first, across files once imports merge — so a child that only says `is_a: anchors` is typed the way linkml-runtime would type it. Boolean metaslots (`required`, `multivalued`) are the exception and stay the child's own: a stated `false` is indistinguishable from silence, and overriding an explicit `false` would be worse than not inheriting.
- **The same slot name defined at several sites is now reported, and `--strict` refuses it — because those definitions silently mint one RDF property IRI.** Two classes declaring same-named `attributes:` are distinct slots in LinkML, but the RDF output derives one property IRI for both: only one definition survives a read-back, and the emitted OWL asserts a single property about every declaring class. The shared load path now names every definition site in one warning (a class attribute, or a class attribute shadowing a top-level slot) with the ways out — rename, share one top-level slot, or give each its own `slot_uri`. Definitions carrying distinct `slot_uri`s mint distinct IRIs and are not reported, and a top-level slot listed by several classes via `slots:` is one slot being shared, which is the supported shape and stays silent. A second property over generated YAML and Turtle inputs pins that both readers now produce the same classes and effective slots.
- **`default_range` now types every output, and the validator enforces scalar types.** A slot with no explicit `range:` takes the schema's `default_range` — but only the JSON Schema writer honored it, so the same slot was typed in one output and untyped in the others: RDF shipped datatype properties with no `rdfs:range`, SHACL shapes had no `sh:datatype` to check, HTML docs showed no range, and `validate` silently passed data like an integer at a string-typed slot. The default is now materialized into the slot definitions at load time, per file: LinkML scopes `default_range` to the declaring schema, so in a multi-file schema each imported file's rangeless slots take that file's own default (never the root's), and a file that declares no default keeps its slots untyped whatever the root says. Every writer and the validator then see a populated range, and none needs to know defaults exist. A slot that states something more specific — an explicit `range`, an `any_of` union, or `maximum_cardinality: 0` — is left alone, and a `default_range` naming nothing the schema defines is reported as a dangling reference instead of failing silently.
- **The validator checks scalar kinds — the whole check was missing, not just the defaulted case.** An explicitly `range: string` slot also accepted `42`. Values are now kind-checked against the range's primitive, agreeing with the JSON Schema the same schema projects: the float family follows number semantics (an integer is a valid float, and an integral float like `5.0` is a valid integer), a union of scalar ranges conforms when any branch matches, and custom `types:` resolve through their `typeof` chain or — for a root type — the XSD datatype their `uri:` names. A range that resolves to no known primitive is skipped rather than guessed at: enums, class references, and dangling names keep their own checks. A wrong-kinded value produces one report naming the value, its kind, and what the range expects, and suppresses the follow-on pattern and bounds checks so one problem yields one report. **Note:** data that previously validated clean may now fail — every wrong-kinded value at a typed or defaulted slot was previously a silent pass.
- **A malformed Turtle file that crashes the underlying parser now comes back as an error instead of taking the process down.** The first extended fuzzing campaign found an input that trips a debug assertion inside the Turtle parsing dependency itself — current latest version, no upstream fix — which meant a hostile or corrupted `.ttl` file could crash any command that reads one. The reader now confines the parse behind a panic boundary, so a malformed file is a returned error whoever's code chokes on it, with the crashing input pinned as a regression fixture.

- **The readers can be fuzzed with arbitrary bytes, on demand.** The OWL/Turtle and LinkML YAML readers parse the one input panschema takes that its operator did not write — a schema fetched as a `github:` dependency — so each now has a fuzz target holding the contract that a malformed file is a returned error, never a panic or a hang. Campaigns start from a committed seed corpus of real schema fixtures rather than noise, and run through an on-demand workflow with a configurable duration, never in the push gate. A crash found by a campaign gets minimized, committed as a regression fixture, and fixed with an ordinary test, so the suite keeps the finding without needing the fuzzer to rediscover it.
- **The test suite now generates its own schemas and checks properties over them: a schema written to Turtle and read back means the same thing, and every byte-stable format renders the same schema to identical bytes twice.** Example tests cover the schemas someone thought to write down, and mutation testing checks those examples assert enough — but it perturbs the code and reuses the same inputs, so neither can find a schema shape nobody considered. These properties do, and shrink any failure to a minimal counterexample. The round-trip property found a real reader defect on its first run (see *Fixed*), plus two recorded asymmetries pinned where they are excluded: an enum read back from OWL returns as a class (the reader has no rule for `owl:oneOf` yet), and two classes declaring same-named attributes collide at one property IRI in RDF. JSON-LD is excluded from the determinism property as a known open finding — its output differs run to run — rather than silently skipped.
- **`[book_link]` accepts a list, so a book fronting several schemas reaches all of them from the toolbar: one entry renders the plain link it always did, several render a drop-down in the same slot.** The motivating case is a domain book that publishes its own schema docs *and* a dependency schema's docs rendered against local instance data — an author cross-checking that each record's expected anchors resolve to real nodes wants both pages open side by side, which needs both separately addressable. It reuses the selector-when-N shape the in-page instance-graph selector already established, so the book-navigation version reads as the same idea rather than a second affordance. Both TOML spellings parse — the `[book_link]` table form is unchanged, keeps its `enabled` switch and its defaults, and needs no edit in any existing book; the `[[book_link]]` array form takes `schema_path` and `label` per entry, where writing an entry is itself the opt-in and an empty list means off. A list of one is byte-for-byte the old single link, which is what makes the list form safe to adopt before a second schema exists. The drop-down is a real button and list rather than a hover menu, so it is reachable by keyboard, closes on Escape or an outside click, and follows the reader's mdbook theme; every href stays `path_to_root`-relative so links resolve under a GitHub Pages project prefix. A typo'd key in an entry is a parse error that names the key, matching what the table form has always done.
- **A multivalued slot with a class range becomes a linking table, so no class is left out of the Postgres projection for being multivalued.** Together with the array columns below, this closes the gap that kept whole schemas from projecting: two real consumer schemas went from 9 and 5 tables to 25 and 18, with nothing skipped. The table is named `<owner>_<slot>` — after the *slot*, not the target class, so two slots onto the same class stay two distinct relationships — with both foreign keys `NOT NULL` and the pair as the primary key, and each key following its side's real primary key rather than a fabricated `_id`. Every multivalued class range gets one, whether the relationship looks like ownership or sharing. LinkML can tell those apart (a class-ranged slot whose target has no identifier is always inlined; with one it defaults to a reference), but a foreign key on the child fails either way in practice: a target class reached from two slots cannot record which parent it belongs to, and that shape occurs in both consumer schemas. The failure modes are also asymmetric — a linking table where one-to-many was meant is a missing constraint with the data intact, while a child-side key where many-to-many was meant is data that cannot be stored at all, discovered late and fixable only by a migration. **List order is not preserved:** LinkML's canonical inlined form is an identifier-keyed dict, ordered lists are opt-in via `inlined_as_list`, and where order is part of the domain, schemas model it with an explicit slot.
- **A multivalued slot with a scalar or enum range becomes a Postgres array column, and a class is taken out of scope only for a multivalued *class* range.** Previously any multivalued slot took its whole class out of the Postgres projection, and the warning named whichever such slot sorted first — so a class blocked by a linking-table problem could be reported as though an array column would fix it. The diagnostic now names the *kind*: `text[]`, `integer[]`, and enum arrays are emitted, while a multivalued class range says it needs a linking table. `required` on such a slot still means `NOT NULL`, which permits an empty array. One deliberate omission is reported rather than emitted: a `pattern` or a value bound on a multivalued slot constrains each element, and Postgres has no `CHECK` form for that over an array column — `arr ~ 'p'` is not an operator, and the `unnest` subquery that would express it is not allowed inside a `CHECK`. Emitting one would produce a script that parses and then fails when the database runs it, which no grammar-level check can catch, so it is dropped and named in a warning alongside the existing skipped-class and skipped-rule diagnostics.
- **New `migrate` command: `panschema migrate --schema <file> --migrations <dir>` writes the schema's Postgres DDL as the first versioned migration file.** `generate --format postgres` emits a full `CREATE TABLE` script, which is useful exactly once — on an empty database. After that a consumer whose LinkML schema drives both generated Rust types and generated DDL was back to hand-writing `ALTER` statements, which is the work the schema was meant to spare them. The migration lands as `V<version>__<schema_name>.sql`, the layout a checksumming versioned runner discovers; the filename shape is pinned by a test carrying the runner's own discovery pattern, because a file that pattern rejects is skipped in silence rather than reported. Three properties follow from how such a runner behaves, and each is enforced rather than documented: the SQL is **byte-identical across runs and machines**, carrying no timestamp and no tool version, since the runner hashes raw SQL with no normalization and a changed hash aborts the next deploy — so a migration omits the `@generated by panschema v…` banner that the regenerated DDL keeps; re-running against an unchanged schema is a **no-op** that neither appends a second copy nor rewrites the first; and a directory already holding migrations panschema did not just write is **refused**, since incremental emission is not built yet and guessing would produce a file a runner might apply. A manifest may declare `migrations = "db/migrations/"` in a `[generate.<name>]` block, but `generate` skips that key — an append-only artifact does not belong in the regenerate-everything command, so `panschema migrate` with no `--schema` is the manifest-driven run. The command writes files only: it never connects to a database and has no apply or rollback mode, and `--help` says so. A generated migration is a draft to review, not an authoritative artifact.
- **panschema ships a Claude Code skill, and tests keep it from going stale.** A coding agent working in a repo that *consumes* panschema previously had to guess the CLI and manifest from a README it might not read, or from source it cannot see — and guessed wrong in practice: a `[generate.<name>]` block with no matching `[schemas.<name>]` is a silent no-op that exits 0, and `source = "path:."` fails because `source` is the remote field while `path` is a separate one. The skill documents the CLI surface, the manifest schema, and the output formats, with those traps stated up front. What makes it different from another README is that the build holds it true: the manifest reference's example is **extracted from the reference file and executed** by a test, so a documented example that stops working fails CI, and the code's own enumerations — registered output formats, CLI subcommands, and every `[generate]` key, the last derived by round-tripping the config through serde — assert that the reference mentions each one, so a new capability cannot ship undocumented. Both mechanisms were verified against their failure modes rather than assumed. Neither checks that prose is *accurate*; the skill says so rather than implying otherwise.
- **`validate` now enforces class-level `rules`, so a conditional requirement is machine-checked by the same command that checks everything else.** A rule like "when `status` is `actual`, `in_environment` and `on_provider` are required" previously rendered on the class card and projected to SHACL, but the native validator skipped it — data violating it reported *conforms*, and the only way to actually check the rule was to run an external SHACL engine over generated shapes. For each record whose class carries a rule, the precondition is evaluated and, when it holds, the postcondition is checked; a failure names the rule (by `title`, or by position when untitled), the class, and the slot that failed. The condition facets match what the SHACL projection already covers, so the two agree on what a rule means: `equals_string`/`equals_number`, `value_presence`, `required`, and both `any_of` forms — alternatives over whole condition sets and over a single slot's value — with numeric bounds, `pattern`, and cardinality inside a condition enforced too. A `range:` inside a condition is a type assertion rather than a value test and is not evaluated, since the slot's declared range is already checked for every record. Because the check lives in the shared conformance core, it reaches the standalone command, `generate --instances`, and `publish` alike, and `--strict` fails on it.
- **New `openapi` output format: `generate --format openapi` emits an OpenAPI 3.1 document from the LinkML schema.** The schema's classes become the document's `components/schemas` — one schema per class — so a service's generated API clients (TypeScript, Swift, …) can be built from the same LinkML source the Rust DTOs come from, instead of the API contract being authored separately and left to drift. OpenAPI 3.1's schema dialect *is* JSON Schema 2020-12, so the component schemas are the JSON-Schema class definitions verbatim (enums, class `$ref`s, `anyOf`, custom-type resolution, inheritance flattening, and value constraints all carry over), with the inter-class `$ref`s retargeted from `#/$defs/<Class>` to `#/components/schemas/<Class>`. `info.title`/`info.version` come from the schema's `title`/`version`. It emits schema components only — LinkML models the data model, not HTTP operations, so the `paths`/operations layer is expected to come from the service code `$ref`-ing these components. Available on `generate --format openapi` and as an `openapi` output in a manifest's `[generate.<schema>]` block; each component is checked as a usable JSON Schema by the `jsonschema` oracle.
- **New `json-schema` output format: `generate --format json-schema` emits a JSON Schema from the LinkML schema.** A schema's classes become a JSON Schema (draft 2020-12) — one closed `object` per class under `$defs`, with each class's effective slots as typed properties (a scalar LinkML range maps to a JSON Schema `type`/`format`; an enum range to a JSON `enum` of its permissible values; a class range to a `$ref` to that class's `$def`; multivalued slots wrapped in `array`), value constraints projected (`pattern` → `pattern`, `minimum_value`/`maximum_value` → `minimum`/`maximum`), a polymorphic `any_of` range as `anyOf` over its branches, a custom `types:` range resolved to its base scalar and facets (following the `typeof` chain or the type's `uri` datatype, carrying its `pattern`), inherited and mixed-in slots flattened onto each subclass object (so a subclass instance validates against its own `$def` without chasing `is_a`), a `required` list from effective cardinality, and `additionalProperties: false`. This is the language-agnostic structured-output contract: an LLM (via a framework like `rig`, or Anthropic/OpenAI structured output) can be constrained to produce valid instances, and any JSON validator can check instance data against the same schema — the JSON an LLM returns *is* a LinkML instance. When the schema declares a `tree_root` container class — now a recognized construct in the IR — the document is rooted at it with a `$ref` (a conforming instance is an instance of that class); otherwise the document is `$defs`-only. Available on `generate --format json-schema` and as a `json_schema` output in a manifest's `[generate.<schema>]` block. Every emitted document is checked with a real, independent JSON Schema validator (the `jsonschema` crate): it must compile as a valid schema, and representative instances must validate as expected (well-formed data passes; missing-required, wrong-typed, and extra-property data all fail). Current coverage is scalar properties; enum/class `$ref`s, `pattern`/bounds constraints, and inheritance flattening are still to come.
- **`--version` now identifies which commit a non-release build came from.** A binary built from `main` and one from the last release both reported the bare crate version, so "rebuild from `main` to pick up the fix" was advice a consumer could not verify, and a months-old binary was indistinguishable from a current one. Builds that aren't a tagged release now report `<version> (<short sha>)`. An install with no git — from crates.io or a source tarball — still reports the bare version, as does a build from the release tag itself, so a released artifact never carries a commit that can't be reproduced.
- **`[generate.<name>]` takes an `instances` key, so a repository can document its own data against someone else's schema.** A repo whose schema is a published dependency rather than a local file now declares its curated A-boxes in `panschema.toml` — `instances = ["data/preview.yaml", "data/catalog.yaml"]`, resolved relative to the manifest — and a manifest-driven `generate` renders the imported schema's docs featuring them, behind the in-page selector, in declaration order. The configured exports receive them too; a format that emits a single A-box rejects several rather than silently choosing one, and a path that isn't there fails naming the schema and the file.
- **A field the class doesn't declare is now a violation.** Writing `colour` where the schema declares `color` used to validate clean, render on the page, and emit as `<…#colour> "red"` — minting an RDF property in the schema's own namespace from a typo, while the slot actually meant stayed absent and unreported. Such a field is now reported per record, naming the field and the class and saying that it renders and emits rather than being dropped; `--strict` fails on it. Because the conformance check now runs on the way into an output, this reaches `validate`, `generate --instances`, and `publish` alike.
- **Instance data is now conformance-checked on its way into an output.** `generate --instances` and `publish` previously reported only dangling references, so a duplicate identifier, a missing required slot, or a bad enum value could be embedded into generated docs — or published to a live site — without a word, even though `validate --data` would have failed on it. Both paths now run the same check the standalone validator runs: violations are warnings by default and hard failures under `--strict`, and `publish` reports them per version rather than aborting, so an old tag stays publishable. One code path decides what conforming means, so the standalone command and the embedding paths can't drift apart.
- **`publish` carries every declared instance graph, not just the exemplar.** All `[[instances]]` entries in `panschema-publish.toml` are built per published version and embedded behind the in-page selector, so a site can show a teaching preview beside the full worked example. `exemplar = true` now means "the dataset the page opens on" rather than "the only one published" — declaration order drives the selector, the flag drives which panel opens, and with none set the first entry opens. A version whose git ref predates a data file publishes without that graph, as before. The "declared but not published" note is gone, since nothing is left unpublished.
- **A schema page can carry several curated instance graphs, switchable in place.** `generate --instances` now repeats: pass a small teaching preview and a full worked example and the Instance Graph section offers both, each labelled, with its own individual cards, provenance line, and node/edge counts. Picking one swaps the cards and re-renders the viz over that A-box, client-side — every declared graph's payload rides in the page. A single instance graph renders as before, with no selector. Formats that emit exactly one A-box (`ttl`, `jsonld`, `rdfxml`, `ntriples`, `instance-graph-json`) reject several files rather than silently merging them.
- **SHACL shapes now express `value_presence` and `any_of` rule conditions.** A rule whose trigger or consequence uses `value_presence` (a slot must be present/absent) or `any_of` (alternative values on a slot, or alternative whole condition sets) previously had no shape form and was skipped with a diagnostic — so the decided-vs-pending pattern ("when `verdict` is present, `approved_by` is required"; "when `verdict` is `approved` or `rejected`…") validated in the docs and Postgres but silently not in SHACL. `PRESENT` now projects as `sh:minCount 1`, `ABSENT` as `sh:maxCount 0`, a slot's alternative values as `sh:or` over `sh:hasValue` shapes (typed from the slot's declared range), and alternative condition sets as `sh:or` over recursively-built condition shapes — all with deterministic named IRIs, oxigraph-verified. A condition side that is only `any_of` is now expressible; genuinely empty sides still skip with the diagnostic.
- **`publish` carries the exemplar instance graph onto the versioned site.** `panschema-publish.toml` accepts `[[instances]]` entries (`name`, `data`, optional `exemplar = true` — at most one exemplar; a second is a parse error, and unknown keys fail loudly). Each published version renders its own ref's data file — the same `git show` extraction the schema uses — so a tag that predates the dataset publishes without an instance graph (a note, not an error), and the edge/worktree build renders the working tree's file. The exemplar appears embedded in each version's schema page with its Instance Graph sidebar entry and provenance line; previously `publish` dropped the A-box entirely, so deployed sites never showed it. Entries not marked `exemplar` are accepted but noted as unpublished until sibling instance pages exist.
- **The instance graph is navigable in the docs, and every individual gets a card regardless of how it was authored.** The sidebar gains an **Instance Graph** entry (with node/edge count badges) whenever the page has an A-box — previously a LinkML instance-data file rendered a canvas with no navigation entry and no cards, because cards existed only for OWL-embedded individuals. Cards now render through one path over the instance model, so a LinkML-data record gets the same card an OWL individual does: its type linked to the class, scalar values, and references linked to the referenced individual's card, with the card's IRI matching the RDF/graph exports' minted identity. The section states its provenance (the instance-data file name, or "embedded in the schema"), and rendering an exemplar beyond a few hundred instances warns that exemplars are curated teaching artifacts — the graph still renders.
- **New `instance-graph-json` output format: the instance graph as its own graph-JSON artifact.** `generate --format instance-graph-json --schema schema.yaml --instances data.yaml --output instances.json` renders the A-box as a typed, traversable graph document — individuals as nodes whose `uri` is the same minted IRI the RDF output uses, reference edges labelled by slot — so a traversal over the graph JSON and a SPARQL query over the RDF agree on which individual is which. One invocation produces exactly the file `--output` names (the schema graph remains `graph-json`'s single document; the two are peer artifacts, not a file plus a derived sibling), and the manifest accepts `instance-graph-json` beside `graph-json` in `[generate.<schema>]`. Without `--instances`, the document is built from the schema's embedded OWL individuals, matching the HTML instance section's source precedence. Every graph document now declares `graph_kind: "schema" | "instance"` so a consumer holding a bare file can tell what it has, and `format_version` bumps to `1.1` — the field defaults to `schema` on read, so documents from before the bump still parse.
- **The RDF outputs can now carry the instance data: `generate --format ttl --instances data.yaml` emits a self-contained knowledge graph.** Every RDF-family format (`ttl`, `jsonld`, `rdfxml`, `ntriples`) accepts `--instances`: each record in the LinkML instance-data file emits as an `owl:NamedIndividual` — typed with its class IRI, labelled with its display name, scalar slot values as data-property assertions carrying XSD datatypes derived from the slot's declared range, and id references as object-property assertions resolved to the referenced individual's IRI. Individual IRIs mint from one shared derivation (the id expanded against the schema's prefixes), so the docs, the graph exports, and the RDF agree on which individual is which. The result is what a triple store loads and SPARQL queries directly — schema and data in one file — verified by loading generated Turtle into a real, independent store and querying individuals by type and across reference edges. Without `--instances`, RDF output is unchanged. A reference to an undefined instance warns by default and fails the build under `--strict`.
- **A class's external `subclass_of` grounding now draws in the schema graph.** A class that grounds into an upstream ontology via `subclass_of` (a single external category named by IRI or CURIE, e.g. `Service → cco:ont00000995`) previously showed nothing in the graph — only internal `is_a` was drawn, so a grounded class looked parentless and an ontology's whole external-grounding story was invisible. Each grounding now draws an edge to a muted, dashed **external category node**, distinct from the schema's own class nodes; classes grounded in the same upstream category share one node, so the graph reads as a small set of upstream anchors. The node is labelled by the category's cached upstream `rdfs:label` when available — the same label cache that names external slot ranges — falling back to the CURIE otherwise, and carries the full IRI for its hover. The standalone `graph-json` output (which has no label cache) uses the CURIE label. Hovering an external node shows its full IRI and the category's cached upstream definition, and the graph legend documents the muted/dashed external node. A "Groundings" graph control — shown only when the graph actually carries external nodes — toggles their visibility (remembered across visits) so a reader can hide the upstream anchors and focus on the schema's own classes. Verified by a unit test on the graph JSON (shared node + edges) and browser tests that the muted node paints and that the toggle hides it.
- **Worked-example individuals now render as a separate instance graph.** An ontology's OWL `NamedIndividual`s (its A-box) draw as their own force-directed graph beneath the Individuals section of the HTML docs — nodes are individuals (teal hexagons, typed and carrying their literal assertions), edges are their object-property assertions between individuals. It is a *distinct* viz from the schema graph, not an overlay: the schema (T-box) graph stays uncluttered, and the instance (A-box) graph reads on its own, right where the individual cards are documented. The graph writer gains `schema_to_instance_graph` (a separate `Individual`-node/`Assertion`-edge graph built from the individuals panschema already ingests); it is emitted only when the schema actually declares individuals. Verified by reading a fixture ontology through the OWL reader and by an end-to-end browser test that asserts the instance canvas paints the individual nodes.
- **`generate --instances data.yaml` renders a LinkML instance-data file as the instance graph.** An A-box can now be authored as a *separate LinkML data file* — a `tree_root` container object whose typed collection slots hold records conforming to the schema — and passed with `--instances`; panschema reads it into its first-class instance model and draws it as the instance graph beneath the Individuals section, staying entirely in LinkML + JSON with no OWL/TTL detour. Each record becomes a typed node keyed by its identifier (the value of an `identifier` slot, or the map key of an identifier-keyed collection); a class-ranged value becomes a reference edge to the target instance (or, for an inlined object, a nested record plus an edge to it), and a scalar value becomes node-level literal metadata. Both the list and identifier-keyed-dict collection forms are read, and reference-vs-inline is inferred from the data's shape rather than a schema flag. This is the read-side companion to the JSON Schema output: the JSON an LLM returns against a class's schema *is* a LinkML instance, and this reads a file of them back for visualization. A reference whose target identifier names no instance in the data is reported as a *dangling instance reference* — naming the referring record, the property, and the missing id — the A-box analog of the schema-side dangling-reference warning and the feedback signal an agent loop uses to self-correct; `generate --strict` turns it into a non-zero exit. The instance-data path drives only the graph for now; the per-record Individuals cards still come from a schema's embedded OWL individuals.
- **New `validate` command: `panschema validate --schema schema.yaml --data data.yaml` checks a LinkML instance-data file against the schema.** A native validator walks each record in the `tree_root` container against its class's effective slots and reports every violation, exiting non-zero when the data doesn't conform and zero when it does — the conformance gate an authoring loop or CI branches on. It checks required-slot presence (a required slot absent from a record, named with its class), slot cardinality (a single-valued slot given a list, or a multivalued slot's value count below `minimum_cardinality` or above `maximum_cardinality`), value constraints (an enum-ranged value that isn't one of the enum's permissible values, a numeric value below `minimum_value` or above `maximum_value` — with a non-numeric value at a bounded slot reported rather than panicked — and a string value that doesn't match its slot's `pattern`, using the same partial-match semantics as the SHACL/Postgres projections), range-kind mismatches (an object where a scalar range is declared, or a non-reference scalar where a class range is declared — the reader records such a value rather than dropping it, so it's caught precisely instead of surfacing only as a downstream "absent" symptom), cross-record reference integrity (a reference whose target names no record in the data), and identifier uniqueness (two top-level records claiming the same id — the same entity inlined and referenced isn't flagged); an identifier supplied as an identifier-keyed collection's map key satisfies its identifier slot, and a data file that isn't a container mapping is a clear structural error, not a panic. It validates natively against the IR rather than through the generated JSON Schema — which doesn't yet project enums, patterns, bounds, or reference typing — so the checks it makes are real. Internally the validator consumes the internal instance model (the A-box hub), not the on-disk format: instance data in any supported format is read into that model and validated through one format-agnostic core, mirroring how a schema in any format becomes the IR before anything reads it. `any_of` polymorphic-range checks build on this in a subsequent release.
- **Cross-package `imports:` — a schema can import a manifest dependency by name.** An `imports:` entry that names a `[schemas]` dependency (rather than a local file) now resolves to that dependency's schema in its own package and merges it, so a layering application composes one or more shared schemas plus its own local classes into a single generated output. Resolution precedence is local file → manifest dependency → built-in, so a real local import is never shadowed by a same-named dependency; local imports stay contained within their package's directory, while a manifest-declared dependency is a trusted jump into its own tree. The imported dependency's prefixes union into the importing schema, so a cross-namespace CURIE resolves. An `imports:` entry that names neither a local file nor a declared dependency fails with a diagnostic naming the entry and pointing at `[schemas]` + `panschema fetch`, instead of a silent drop. An application can import several shared schemas at once — including a diamond where two of them import a common base, which merges once — and a class in the app resolves references to any imported class. When two dependencies define the same element *differently* and neither is the importing schema, the command fails naming both source files instead of silently picking one by import order; a root-vs-import override stays a deterministic warning (the importing schema wins).
- **Manifest-driven `generate` fans out to every writer, not just HTML and Rust.** A consumer project's `panschema.toml` `[generate.<schema>]` block now accepts `postgres`, `shacl`, `ttl`, `jsonld`, `rdfxml`, `ntriples`, and `graph-json` output paths alongside `html` and `rust`, and `panschema generate` (with no `--schema`) emits each configured format for every manifested schema in one run — so a relationally-backed application gets its Postgres DDL from the same manifest that produces its Rust types. A writer that errors fails the command naming the schema and format it was producing; an unconfigured format is simply not emitted.
- **New `shacl` output format: `generate --format shacl` emits a SHACL shapes graph from the LinkML schema.** A schema's declared value-constraints are now machine-checkable by any SHACL engine, not just visible in the docs — one `sh:NodeShape` per class (targeting the same class IRI the OWL output declares) with a `sh:property` shape per slot carrying its constraints: range → `sh:datatype` (scalar) or `sh:class` (class-valued), `required` and `minimum_cardinality` reconciled into a single `sh:minCount` (explicit cardinality wins, so the two never contradict), `maximum_cardinality` → `sh:maxCount`, `pattern` → `sh:pattern`, and `minimum_value`/`maximum_value` → `sh:minInclusive`/`sh:maxInclusive`. A class `rule` (a conditional requirement like "when `status` = `actual`, `region` is required") becomes a conditional `sh:or ( [ sh:not <precondition-shape> ] <postcondition-shape> )` — the SHACL-Core analogue of an if/then constraint — with the equality checks projected as `sh:hasValue`. The output is a standalone Turtle shapes file (separate from the OWL/TTL output), and every generated graph is loaded into a real, independent triple store (`oxigraph`) in the tests to confirm the shape triples are well-formed and queryable. Cross-instance `unique_keys` uniqueness (which SHACL Core can't express without SPARQL) is still to come.
- **Generated HTML documentation is now checked against a real HTML5-conformance parser.** A browser silently repairs malformed markup, so passing the existing browser-based end-to-end tests was never proof the generated HTML was actually spec-valid. Every generated page is now parsed with the same HTML5 engine Servo/Firefox use, and any parse error (mis-nested tags, unclosed elements, and the like) fails the test suite. No output change for users — this only strengthens what confirms the output is correct.
- **Generated RDF/OWL output is now checked against a real, independent triple store.** Every RDF-family writer (TTL, JSON-LD, RDF/XML, N-Triples) shares one serialization core, so nothing previously confirmed the resulting graph was sane beyond panschema's own reader parsing it back. Generated TTL is now loaded into an in-memory `oxigraph` store and queried with SPARQL — e.g. confirming every class actually carries an `rdf:type owl:Class` triple and a declared `subClassOf` resolves to a real triple — catching graph-level mistakes a shared internal blind spot wouldn't self-report. No output change for users — this only strengthens what confirms the output is correct.
- **Generated Postgres DDL is now confirmed to apply against a real database.** Passing syntax validation only proves the output is well-formed SQL, not that it actually works — a foreign key referencing a column that doesn't exist, for instance, is syntactically fine but fails at apply time. A representative multi-class fixture (an enum, both kinds of primary key, a foreign key between them) is now applied against a disposable, real Postgres database in CI, catching that class of error. No output change for users — this only strengthens what confirms the output is correct.
- **New `postgres` output format: `generate --format postgres` emits Postgres DDL from the LinkML schema.** A relationally-backed application can now get its database schema from the same LinkML source as its Rust structs, with no hand-written SQL. Current coverage: one `CREATE TABLE` per concrete class with its effective scalar attributes as typed columns (a column is `NOT NULL` when the slot's effective lower bound requires it — `required`, or an explicit `minimum_cardinality ≥ 1`); enum-range slots get a `CREATE TYPE ... AS ENUM` declared before any table references it; the effective `identifier` slot becomes the primary key, or a synthesized `id uuid PRIMARY KEY DEFAULT gen_random_uuid()` when there isn't one; a single-valued class-range slot becomes a foreign key column named after the target's actual primary key column, added via a deferred `ALTER TABLE ... ADD CONSTRAINT` after every table is declared (so declaration order and cycles between classes never matter); mixin attributes flatten into every class that mixes them in, matching how the Rust writer already flattens them; an abstract class gets no table. Every emitted identifier — table, column, enum type, and constraint names — is double-quoted, so a class named `Order` (a SQL reserved word) produces applicable DDL, and a name crafted to escape the identifier position cannot alter the statement. Class- and slot-level constraints are now enforced by the database, not just documented: `unique_keys` become table-level `UNIQUE` constraints (a key naming a slot the class doesn't have is dropped rather than emitting a broken reference), a slot `pattern` becomes an inline `CHECK (col ~ '...')`, `minimum_value`/`maximum_value` become an inline `CHECK` bounding the column, and a class `rule` (a conditional requirement like "when `status` = `actual`, `region` is required") becomes a conditional `CHECK (NOT (precondition) OR (postcondition))` — a rule with no single-column `CHECK` form (one-sided, or a `range`/cardinality condition) is skipped with a warning naming it rather than emitted broken. A class using `is_a`, a multivalued slot, `any_of`, or referencing another skipped class is itself skipped with a warning naming why, rather than emitting broken DDL — multivalued columns and `is_a` support are not modeled yet. Every rendered fixture is checked against `pg_query` — a binding to Postgres's own C parser — confirming it's genuinely valid Postgres SQL, not just a Rust string that matches this codebase's own expectations, and a representative fixture is additionally applied against a real, disposable Postgres database in CI.
- **Class-level `unique_keys` now render on the class card.** A class's uniqueness constraints (`unique_keys:` — named tuples of slots whose combined values must be unique) previously parsed and silently vanished. The class card now shows a "Unique keys" row listing each key's slot tuple with its optional description. Each referenced slot is checked against the class's effective slot set (inherited, mixed-in, and refined slots included); a key naming a slot the class doesn't have produces a warning at generate time, so a typo'd or stale constraint is caught rather than rendered broken. Enforcement against instance data remains the consuming application's responsibility. Beyond the docs, `unique_keys` also project to Postgres `UNIQUE` constraints (see the `postgres` format entry); for formats that don't project them (`rust`, `ttl`, ...), generating warns that they won't appear in that output, naming the format actually requested, so the gap isn't silent.
- **Class-level `rules` now render on the class card.** A class's conditional constraints (`rules:` — precondition/postcondition pairs over `slot_conditions`) previously parsed and silently vanished. The class card now shows a "Rules" section: each rule's title/description plus a human-readable "when … then …" sentence built from its conditions (`range`, `required`, cardinality, value bounds, `pattern`, `equals_string` / `equals_number` equality checks, `value_presence` presence checks, and `any_of` alternatives — both a single slot's alternative values (`verdict` is `approved` or `rejected`) and alternative whole condition sets) — e.g. "when `status` = `actual`, then `region` is required", or "when `verdict` = `approved` or `verdict` = `rejected`, then `approved_by` is present". (`value_presence` and both `any_of` forms were previously parsed away and left a rule looking like a bare description — a decided-vs-pending rule showed its consequence with no trigger; all now round-trip in the IR and render.) The graph JSON export now carries each class's rules (title, description, and the same rendered summary) in its node metadata, where previously the graph omitted rules entirely — so the schema-graph hover can surface them. Each **slot** card now also gains a "Rules" section listing every class rule that references that slot (on either the trigger or governed side), naming the class and the rendered summary — so a reader on a conditionally-required slot sees the rule that constrains it; because the graph hover / pinned card reuses the slot's HTML card, the same section shows when you hover or click a slot node. Beyond the docs, `rules` also project to Postgres conditional `CHECK` constraints and SHACL conditional shapes (see those format entries); for formats that don't project them (`rust`, `ttl`, ...), generating warns that they won't appear in that output, naming the format actually requested, so the gap isn't silent.
- **Warns on silently-dropped LinkML class constructs.** panschema parses but does not model many class-level LinkML keys (e.g. `rules`, `unique_keys`, boolean class expressions); previously a schema could declare one and have it vanish from every output with no signal. `generate` now warns on **any** unmodeled class key by default — naming the key and the class (e.g. "`rules` on class `Deployment` is parsed but not modeled; it will not render or emit"). The ignore-list of keys that don't warn starts empty and grows only as a specific key is identified as safe to silence; warning by default (rather than an allowlist of known constructs) is what catches drops that weren't anticipated, including a producer's typo of a real field. `generate --strict` turns these warnings into a non-zero exit (both `--schema` and manifest modes), so CI can fail a build that would silently drop a constraint. Output is otherwise unchanged — the construct is still dropped, just no longer silently.
- **`mdbook-panschema install` — a maintained mdbook→schema toolbar link.** A new `mdbook-panschema` binary installs a toolbar button that links an mdbook book to its panschema-generated schema docs, the way `mdbook-admonish install` drops its assets: `mdbook-panschema install [dir]` (`dir` defaults to the current directory) writes `schema-link.js` / `schema-link.css` into the book and wires them into `book.toml`'s `additional-js` / `additional-css`, idempotently (re-run after an upgrade to refresh). With `[book_link]` absent or `enabled = false`, `install` is a no-op. Replaces the per-book custom JS/CSS every consumer previously hand-rolled.
- **Local `imports:` now resolve and merge at load time.** A LinkML schema that lists other local files in `imports:` previously had those entries parsed and then ignored, so the schema rendered only the root file's elements. Each import naming a local file (resolved relative to the importing file; `.yaml`/`.yml`/`.ttl`, extension optional) is now loaded and folded into the root before any writer runs — its `classes`, `slots`, `enums`, `types`, and `prefixes` union into one schema, with the importing file winning on a name collision. Docs, codegen, RDF, and graph output all see a single self-contained schema, so a vocabulary split across files renders as one. Import resolution runs through one shared load path used by `generate`, `serve`, and `publish` alike, so a split schema also previews correctly under the dev server's hot reload and in published output — previously only `generate` resolved imports. That shared path also surfaces the schema-level diagnostics (unmodeled constructs, `unique_keys` naming a slot the class lacks) on all three commands, not just `generate`.
- **Dangling references now produce one clear warning instead of six silent degradations.** A slot `range`, a class `is_a` parent or `mixin`, or a slot `inverse` that names nothing the loaded schema defines — no class, enum, `types:` entry, or LinkML built-in primitive — previously degraded differently and silently in each writer: the graph dropped the edge, the RDF/SHACL writers minted an IRI from the bare name, Postgres fell back to `text`. Loading a schema now reports each unresolved reference once, naming the referrer and the missing name, on `generate`, `serve`, and `publish` alike; `generate --strict` turns it into a non-zero exit. Valid primitive ranges are never flagged (the full LinkML built-in type set resolves), and a schema's own `types:` entries resolve too. Imports resolve transitively (imports of imports), and a file reached through two paths — a diamond — is loaded and merged exactly once. When two files define the same name, identical definitions are silently unified while differing ones surface a warning naming both the kept and dropped source files (the importing file still wins). A self-import or an import cycle — direct or transitive — is reported as a clear error rather than looping. Built-in and remote imports are recognized and skipped as no-ops: the standard `linkml:*` modules (e.g. `linkml:types`), and any CURIE or URL that expands to a remote `http(s)` URI, name well-known schemas rather than local files, so a schema can import LinkML's built-in types the canonical way without codegen failing.
- **Vendored dogfood-schema regression fixtures + weekly release monitor.** Every released (tagged) version of the real dogfood schemas is checked in as a frozen snapshot under `tests/fixtures/dogfood/<repo>/<tag>.yaml` and exercised by panschema's own tests: each vendored release is read, rendered to Rust, and validated with `syn::parse_file`, and the latest release per schema is additionally `cargo build`-compiled in a scratch crate (older tags stay at the parse check to keep CI bounded). Supported forms: the enum form `"Enum(value)"` (or the bare `"value"` resolved against the slot's range enum) maps to the matching variant; the scalar forms `int(N)`, `float(F)`/`double(F)`, `string(S)` (escaped), and boolean (`true`/`false`) map to the field's `i64`/`f64`/`String`/`bool` literal. An `ifabsent` that doesn't parse or resolve falls back to the `Option<T>` field with a warning comment rather than a broken default. The slot card also gains a "Default" row showing the value readably (`planned`, `8080`, `"svc"`, `true`).

The entity card now shows an "Examples" section listing each value with its description when present, so a reader sees what a valid value looks like. LinkML `examples` has no standard RDF predicate, so it is documentation-only.

The entity card now shows an "Aliases" row of comma-joined synonyms and a "See also" row of links — each `see_also` URIorCURIE is CURIE-expanded into a hyperlink, falling back to plain text when its prefix isn't declared. The generated RDF emits one `skos:altLabel` per alias and one `rdfs:seeAlso` per reference on the class or slot IRI, so synonyms and cross-references are discoverable both in the docs and downstream.
- **`deprecated` lifecycle metadata now renders and emits to RDF.** Marking a class, slot, enum, type, or the schema itself `deprecated: "<note>"` previously parsed and silently vanished. The entity card now shows a "Deprecated" badge with the migration note (on slots the badge rides the Characteristics row), and the generated RDF emits `owl:deprecated true` on the class or slot IRI — so a sunset element reads as sunset in the docs and downstream consumers can detect it.
- **Numeric value bounds on slots now show on the card.** A slot with `minimum_value` / `maximum_value` (e.g. a `strength` bounded `0.0..1.0`) previously parsed and vanished; the bounds now render as `≥`/`≤` badges on the slot card, read distinctly from the `min..max` cardinality badge. (Emitting them as an `owl:withRestrictions` datatype facet in the RDF — for reasoner-checkability — is a tracked follow-up.)
- **OWL relationship characteristics on slots now render and emit axioms.** A slot declared `symmetric`, `asymmetric`, `reflexive`, `irreflexive`, or `transitive` (LinkML's relationship metaslots) previously parsed and silently vanished. Each set characteristic now shows as a badge on the slot card *and* emits the matching `owl:<Name>Property` `rdf:type` axiom in the generated RDF — so a reasoner can use, e.g., `owl:TransitiveProperty` to infer the transitive closure. The object-vs-datatype property type is emitted as before; characteristics sit alongside it.

Both gain sidebar nav entries with counts, `[[Name]]` cross-references resolve to the new `#enum-<name>` / `#type-<name>` cards, and the schema graph's hover reuses these rendered cards for enum and type nodes — so every node kind the graph draws now has a matching doc card, and the hover can't drift from the page. Sections are omitted when the schema declares no enums or types.

Hovering an enum shows each value's description on tooltip (with its `meaning` IRI carried for future linking). The reconciliation lives in one shared resolver view, so every writer that displays cardinality gives the same answer.

- **Schema package manager.** Cargo-style dependency management for LinkML schemas. Every schema dependency is a "package": a directory containing `panschema-publish.toml` plus the main schema file it references at `[files].main`.
  - **Publishing standard**: `panschema-publish.toml` lives at the package root and declares the schema's authoritative name, version, LinkML target version, and main-file location. Schema authors publish through this file; consumers verify against it.
  - **Manifest**: `panschema.toml` in the consumer project declares `[schemas.<name>]` dependencies and per-schema `[generate.<name>]` codegen config. Cargo-style discovery (walk up from CWD).
  - **Lockfile**: `panschema.lock` records resolved version + SHA-256 checksum of each schema's main file. Committed alongside `panschema.toml`. Drift detection covers both checksum and version. (A `revision` field is reserved for future provenance; populated only when a source exposes a stable commit identifier — currently always `None`.)
  - **Source protocols**: `path:` for local packages, `github:owner/repo` for tagged GitHub commits. Both go through the same package model. Other protocols (`gitlab:`, `zenodo:`, `https:`) deferred to later releases.
  - **Github source**: anonymous tarball fetch from `codeload.github.com/<owner>/<repo>/tar.gz/refs/tags/v<version>` (no API rate limit). The tarball's top-level directory is `<repo>-<version>/`; the cache extracts to `~/.cache/panschema/github/<owner>/<repo>/<version>/<repo>-<version>/` with `fs2` file locking. Pluggable `TarballSource` trait for future protocols and for tests. Skips `pax_global_header` pseudo-entries that GitHub codeload includes. Symlink hygiene refuses paths that escape the extracted directory.
  - **Commands**:
    - `panschema init` — producer-side scaffolding. Writes a `panschema-publish.toml` in CWD. Three input modes: explicit flags (`--name X --version Y --main schema.yaml`), `--from <linkml.yaml>` (pre-fills name + version from the LinkML file's metadata), or no args (defaults to CWD basename + `0.1.0` + `schema.yaml`). Refuses to overwrite an existing publish file; `--force` opts in. After writing, prints a per-field provenance summary (explicit / from `--from` / default) so the user can see where each value came from. Post-write validation warns if the main file is missing or doesn't parse but still writes the publish file.
    - `panschema release` — producer-side version bump, modeled on `cargo release`. `--level patch|minor|major` does literal semver bumps (`0.x.y --level major` → `1.0.0`); `--version <x.y.z>` sets an exact value. Default behaviour is bump-only — prints the suggested git commands so the user can complete the release manually. `--git` runs `git add` + `git commit -m 'release: v<ver>'` + `git tag -a -m 'release v<ver>' v<ver>` (annotated tags, the only kind `git push --follow-tags` pushes); refuses on a dirty working tree or an existing tag. `--push` (requires `--git`) also runs `git push --follow-tags`. `--dry-run` prints the plan without writing or running anything. Refuses no-op bumps (`--version <current-version>`) with a clear "tag manually" hint. Refuses to release while the LinkML main file's `version:` field disagrees with publish.toml's `[schema].version`. Manifest edits go through `toml_edit` so comments survive.
    - `panschema add <spec>` — single positional spec, either `github:owner/repo@version` or a filesystem path to a package directory. Schema name is inferred from `panschema-publish.toml`; `--name <alias>` overrides. Writes only the `[schemas.<name>]` entry — the `[generate.<name>]` block is the user's to add when they want codegen output. The writer emits a single flat Rust module per schema with: structs for concrete (leaf) classes; marker traits for classes used as `is_a` parents or mixins, with supertrait bounds following the LinkML inheritance chain and `impl Trait for Struct {}` blocks per concrete descendant; flattened slot inheritance (parent + mixin slots merge into the consuming struct) with `slot_usage` overrides applied per-class; LinkML enums as Rust enums with `#[serde(rename)]` on variants whose text isn't a valid Rust identifier; primitives mapped to `String` / `i64` / `bool` / `f64` / `chrono::DateTime<Utc>`; `Option<T>` / `Vec<T>` framing for optional / multivalued slots; polymorphic `any_of` ranges as per-slot `#[serde(untagged)]` union enums (branches without an explicit `range:` inherit the slot's outer range); trait-only-class slot ranges as `<Name>Kind` closed enums of concrete descendants, with `String` fallback + breadcrumb comments when a trait class has no concrete descendants; `Box` wrapping for class-typed single-valued fields to break recursive layout cycles; doc-comments from LinkML descriptions; per-field `#[serde(rename = "...")]` so the LinkML wire format round-trips. Ergonomic derives: every struct gets `PartialEq`, plus `Default` when all fields are conservatively default-able (`Option<T>` / `Vec<T>` always count; required primitives that implement `Default` qualify too). Every emitted enum carries `#[non_exhaustive]` so adding permissible values or subclasses to a schema doesn't break downstream `match` statements. Robust against malformed inputs: circular `is_a` / `mixin` chains terminate cleanly via visited-set guards rather than overflowing; unresolved global slot references emit `// WARNING:` comments rather than silently dropping fields. Generated code depends on `serde` and `chrono` in the consumer's `Cargo.toml`. Renderers are generic over `std::fmt::Write`, so `RustWriter::render_into(&mut sink, schema)` streams directly into any sink without an intermediate `String` allocation; `render(schema) -> String` remains as the convenience wrapper. Recursive `Eq + Hash` analysis: a struct, `<Name>Kind` closed enum, or `any_of` union derives `Eq + Hash` only when every transitive field type does (`f64` family disqualifies; `chrono::DateTime<Utc>`, `NaiveDate`, `NaiveTime` qualify; LinkML enums always qualify). Self-recursive class fields via `Box<T>` preserve the inner trait set; the fixpoint terminates because the support bit only flips from `true` to `false`. Each concrete struct also gets a `pub fn new(<required_fields…>) -> Self` constructor (optional fields default to `None`, multivalued to `Vec::new()`) so consumers survive schema additions of optional fields without breaking calling code; structs with no required-single fields skip the constructor since `Default::default()` already covers the empty-arg case.

### Fixed
- **`cargo install panschema` works from crates.io again.** The published package is now self-contained: the WebGPU visualization bundle ships inside the crate, so installing needs neither the workspace nor `wasm-pack` — the requirement that had silently broken crates.io installs once the bundle became a hard build input. Publishing itself moved to crates.io trusted publishing (short-lived OIDC tokens, no long-lived registry secret) and runs from the release pipeline after the binaries build.
- **The Claude Code plugin manifests declare the project's actual license.** Both carried `MIT` while the crate, the `LICENSE` file, and GitHub's detection all say Apache-2.0.
- **The slot-`is_a` subset check fires for class-ranged slots.** A dataset container's class-ranged slot holding bare identifiers — LinkML's non-inlined reference form — dropped those values at ingestion (only inline record mappings were read), so a specializing slot's containment check had nothing to compare and silently passed data it should reject. Bare identifiers in a class-ranged collection now ingest as references, so they validate — containment and reference integrity both — and render like any other reference.
- **A dataset container's multivalued scalar slots keep their values.** A list of scalars on the tree-root record (`keywords: [a, b]`) was neither a collection of records nor a single metadata scalar, so ingestion silently dropped it: the values didn't render, and `validate` never saw them — a required multivalued scalar on the root passed validation while absent from the data. The values now land on the root record like any record's (and show in the dataset metadata as the joined list), so they render and validate.
- **Postgres columns and Rust fields for custom `types:` now take the base primitive the type resolves to.** A slot ranging over a custom type (`Score: {typeof: integer}`, or a root type declared by its `uri:` alone) fell through to the fallback `text` column, and the generated Rust named the custom type verbatim — a type the generated code never declares, so the module did not even compile. Both writers now resolve ranges the same way the RDF, SHACL, and JSON Schema outputs and the validator do — through the `typeof` chain, or the XSD datatype a root type's `uri:` names — so every projection agrees on what a custom type is. A `types:` entry that resolves to no primitive keeps the widest lexical mapping (`text` / `String`).
- **The `owl:versionIRI` is well-formed whichever way the schema `id:` is spelled.** A schema id ending in `/` — the common spelling — produced a doubled slash in the version IRI (`…/wine//0.2.0`), and an empty path segment is significant in a URI, so anything resolving or joining on the version IRI (a w3id redirect, an import by version, a triple store) saw a different resource than intended. The id and version now join with exactly one separator; `owl:versionInfo` was always correct.
- **An OWL/Turtle input's classes now own the properties their `rdfs:domain` declares, so code generation from OWL input produces populated output.** The reader stored every property at schema level with its domain recorded but never added it to the owning class's slot list, and the shared slot resolver — which the Rust, Postgres, SHACL, and JSON-Schema writers all consult — therefore saw every OWL-read class as having no slots: empty structs, tables with only a surrogate key, shapes with no property constraints, objects with no properties, from an ontology that plainly declares its fields. Two things masked it. No code-generation test used an OWL input (all fed YAML, where slots attach to classes directly), and the HTML docs render properties as a slot-centric section with links back to their domain classes, so the one output anyone eyeballed looked complete. Found by a generated-schema round-trip property on its first run, shrunk to a one-class, one-slot counterexample. A property with no declared domain still belongs to no class in particular and stays schema-level.

- **A SHACL shape for an enum-ranged slot now closes the value set with `sh:in`, so data carrying a value the enum doesn't permit fails validation instead of passing unconstrained.** The shape previously carried no range constraint at all for an enum: `sh:datatype` is only emitted for a built-in primitive (correctly — there is no XSD datatype for an enum to fabricate), which left the slot entirely unchecked by any SHACL engine. The list holds the same value IRIs the A-box asserts — the derived `{enumIRI}/{key}` form, or a value's `meaning:` IRI where declared — so shapes and data agree on what a value *is*. It is an RDF collection with deterministic named node IRIs rather than blank nodes, matching how the conditional rule shapes stay stable and queryable across runs. A rule **condition** on an enum-ranged slot is deliberately left open: the condition carries the slot's range only to type its literals, and adding a closed set beside the condition's own `sh:hasValue` would leave a precondition nothing can satisfy — which makes `sh:or ( [sh:not pre] post )` vacuously true and silently stops enforcing the rule.

### Changed
- **Each writer now owns its "couldn't project X" warnings through one surface, so every command that renders a format emits identical diagnostics from one call.** Previously the warning loops were hand-copied per command — format-gated blocks in one command and a duplicate set in another — and a new gap class had to be wired into every copy by hand. Warning text is unchanged; the typed diagnostic functions stay public for callers that want data rather than prose.

- **The agent skill installs as a plugin, so it updates with the tool instead of rotting as a copy.** panschema now hosts its own Claude Code marketplace: `/plugin marketplace add padamson/panschema` then `/plugin install panschema@panschema`, with `/plugin update panschema` picking up later releases — the same mechanism the sibling tools use, so enabling all of them is one workflow. The skill moved from `.claude/skills/` (project-local, and therefore visible only when working *inside* panschema — backwards for a skill written for consuming repos) to the plugin's `skills/` directory, which is the single copy that ships. Two tests keep the packaging honest: the plugin's declared version must equal the crate's, so a consumer pinning a release gets the skill that describes it, and the skill must exist only in the plugin directory, so a project-local duplicate can't reappear and drift. Consumers no longer need a panschema checkout to get the skill.

- **LinkML's compact dict form is read instead of silently dropped, and the inlining flags are modeled.** When a class has exactly one slot beyond its key, LinkML lets a dict entry map the key straight to that value — `prefixes: {dcterms: http://…}` is the canonical shape. Such entries previously vanished without a word: the reader required every record to be a mapping, so a conforming file lost those records while everything else validated clean. A scalar dict entry now expands into the ordinary record shape (the key identifying the record, the value filling the class's one non-identifying slot) before building, so downstream never sees the compaction. An entry whose class has zero or several candidate slots is *not* guessed into a record — the compact form is only defined for the exactly-one shape, and inventing a fact about which slot the scalar fills would be worse than the silence being fixed. The `inlined` and `inlined_as_list` slot properties are now carried by the IR as declared (tri-state, since LinkML's default depends on whether the range class has an identifier); the reader still accepts data by shape rather than enforcing them — enforcement would newly flag data that inlines without declaring `inlined: true`, so it is deferred rather than slipped in.

- **A schema declaring several `tree_root` classes now says so.** The LinkML metamodel recommends at most one tree root per schema. panschema supports several — each dataset is read against the root it conforms to — but the deviation from that recommendation was silent. Loading such a schema now prints one warning naming the roots and noting that other LinkML tooling may not honor per-dataset selection. It is a note, not an error, and `--strict` does not promote it: a two-root schema is valid LinkML being used deliberately, and the warning exists so that choice is visible, not to punish it.

- **`key` is modeled, and scoping now follows LinkML's own uniqueness split.** LinkML gives identity two forms: an `identifier` value is unique *everywhere* — the same id anywhere denotes one individual — while a `key` value is unique only *within its container*. panschema previously modeled only `identifier` and, when per-dataset scoping shipped, scoped it — quietly giving the global construct local semantics. `key` is now a first-class slot property: a key slot identifies its records (as `identifier` does), becomes the Postgres primary key when no identifier exists, and is what **scoping keys on** — a key-identified record mints beneath its dataset root's IRI, so the same key in two datasets is two individuals. `identifier` recovered its spec meaning: an identifier-carrying record mints unscoped in the schema namespace and is the same individual whichever dataset states facts about it. The authoring rule is now one line each way: mark a class's id slot `key: true` when its records belong to their dataset (an estate's deployments, a study's acts), `identifier: true` when they are the same thing everywhere (a provider, a source document, the dataset root itself — the root's identifier is what makes it the scope).

- **Classes, slots, and enums without an explicit URI now mint the IRI LinkML itself would mint.** An element that declares no `class_uri`/`slot_uri` previously fell back to `{schema id}#{Name}`; LinkML's rule is `{default_prefix}:{Name}`, so the same schema produced different T-box IRIs through panschema than through linkml-runtime or gen-owl, and cross-tool RDF joins failed silently — while *instance* IRIs already followed the LinkML rule, leaving the A-box and T-box of one output disagreeing about their own namespace. The fallback now expands the element name against `default_prefix` exactly as instance ids do (`https://example.org/wine/Wine`, not `https://example.org/wine#Wine`), the derivation is unified so every site that names a class or slot — parents, mixins, domains, ranges, union members, inverses — emits what that element's own declaration would, and a schema with no usable `default_prefix` keeps the fragment form, since LinkML has nothing to expand against there either. Declared `class_uri`/`slot_uri` values are untouched. **This changes emitted IRIs** for schemas that declare a `default_prefix` without explicit per-element URIs; regenerate downstream artifacts once.
- **The instance section reads graph-first, and each dataset introduces itself.** The section is now dataset(s) → Graph → Individuals — the overview graph before the itemized cards, mirroring how the schema side reads — under a heading of `Instance Graph` for one dataset or `Instance Graphs` with the selector for several (the sidebar entry matches). Each dataset opens with a metadata block: the data file's own top-level scalar values (`title:`, `description:`, …) — which the loader previously read and silently dropped — followed by the source line. Switching datasets swaps the metadata, graph, and cards together, and per-dataset anchors survive the reorder.
- **The CLI has one spelling per action: every invocation goes through a subcommand, and the schema flag is `--schema` everywhere.** The bare no-subcommand form (`panschema --schema x --output y`) is removed — it duplicated `generate`, and its globally-declared flags leaked into every other subcommand's `--help`. `panschema` alone now prints help. Alongside it, `validate`, `generate`, and `serve` all name their schema input `--schema` (`validate --schema … --data …`, `generate --schema … --instances …`) — both of a command's inputs say what they are, instead of one being called `--input`. Format-specific rendering flags now warn when a format ignores them (`--instances`, `--no-graph`, `--viz-mode` on a non-consuming format), matching the loud-about-gaps convention, rather than being silently dropped. Breaking for scripts using the bare form or `--input`, acceptable pre-release.
- **Rule-touched nodes now carry a persistent amber ring on the graph.** Every node a class rule touches — a trigger *or* governed slot, and the class that declares the rule — wears a thin amber ring at rest, so a reader spots which fields and classes a rule relates at a glance instead of only on hover. This is exactly the set that lights up when the rule is hovered, so nothing appears on hover that wasn't already hinted at rest. Hovering a rule entry then gives that rule's participant nodes a thicker, larger amber ring, so the focused rule reads above the persistent baseline. When a node is both selected and rule-touched, the blue selection ring sits outside the amber rule ring so both read rather than the blue burying the amber. A new "Rings" section in the graph legend explains all three node rings — persistent (in a rule), pronounced (rule participant, on hover), and blue (selected) — each drawn on the real node kind it decorates (amber on a green slot pill, blue on a blue class circle, never an impossible blue pill), by the same code and at the same stroke width as the graph (and dpr-corrected), so the key matches what's on screen instead of rendering thicker.
- **Hovering a rule highlights its participant nodes on the graph.** Hover a rule entry in a class or slot card — in the docs, or in the graph's hover/pinned card — and the rule's trigger and governed slots plus its owning class light up with a pronounced amber ring on the schema graph, revealing the fields a conditional rule ties together without cluttering the graph with permanent edges. Moving off clears it.
- **Clicking a graph node pins its full card open, replacing the minimal details panel.** Clicking a node used to pop a small top-right panel showing only label / type / id / connections. It now pins the same rich card you get on hover — the entity's actual rendered doc card — with a close (×) button; hovering another node while pinned leaves the pin in place, and closing the card keeps the node selected. One card, one source of truth, for both hover and click. A pinned card also carries a drag handle, so it can be repositioned off the nodes you want to inspect; dragging the handle moves the card while its links and rule entries stay clickable.
- **Graph layout picker reordered to guide you to the right layout.** The dropdown now leads with **SGD (default · fast quality)**, followed by the other cluster-separating stress layouts (Stress majorization, then Hierarchical), then **Force-directed (interactive)** and Kamada-Kawai. SGD is marked as the default, and Force-directed is relabeled to its real strength — the interactive layout (drag a node and the rest relax) — rather than implying it's the one to reach for when you want clusters to read. (The stress family minimizes the difference between on-screen and graph distance, so it separates clusters by construction; force-directed has only local forces and can't, which is why the default and the ordering point at SGD/Stress.)
- **The graph hover reuses the entity's HTML card — one source of truth.** Hovering a class or slot node in the schema graph now shows that entity's actual rendered card (the same `#class-…` / `#slot-…` card from the doc body), so the hover and the page can't drift. As part of this the slot card was brought up to parity with everything the hover used to show on its own: a slot's card lists every class it's a domain of (a slot can belong to several), its validation `pattern`, an `identifier` flag, and explicit cardinality bounds (`min..max`), alongside required / multivalued / inverse and mappings. (Enum and type nodes, which have no card section yet, keep a compact built-in hover.)
- **"slot" is now the single term for a schema relation across the docs.** The HTML doc previously called a relation a "property" (a "Properties" section, sidebar entry, and an `Object Property` / `Datatype Property` badge) while the graph called the same thing a "slot" — two vocabularies for one concept. The doc now says "slot" everywhere, matching panschema's LinkML model and the graph: the section, sidebar entry, and heading read **"Slots"** (`#slots` anchor), and each card carries a single **"Slot"** badge — the object-vs-datatype distinction is conveyed by the card's Range row (a class link vs a datatype name). This holds regardless of source format; an OWL-imported schema also reads as "slot" because the reader normalizes to the LinkML IR before rendering. The `#properties` anchor and `#prop-<name>` card ids become `#slots` and `#slot-<name>` — a breaking change to external deep links, acceptable pre-1.0. See [ADR-006](docs/adr/006-slot-terminology.md).
- **Schema graph layout dependencies bumped: rand 0.8 → 0.10 and getrandom 0.2 → 0.4 (with `wasm_js` backend).** The fork of `egraph-rs` that panschema-viz pins for its layout sub-crates (`petgraph-drawing`, `petgraph-layout-kamada-kawai`, `petgraph-layout-stress-majorization`, `petgraph-layout-sgd`) was bumped through rand 0.9 to 0.10. panschema-viz follows so the tree resolves to a single rand and a single getrandom (no dual-version mismatch). getrandom 0.4 selects the `wasm_js` backend via its feature flag alone — the `--cfg getrandom_backend="wasm_js"` rustflag that getrandom 0.3 briefly required is no longer needed, so the workaround `panschema-viz/.cargo/config.toml` introduced for the 0.3 round is removed. SGD layout output remains deterministic across runs (the determinism test continues to pass), though rand 0.10's internal stream differs from earlier versions so absolute coordinates may differ from previous releases.
- **Slot resolution moved to a shared `linkml_resolve` module.** `panschema::linkml_resolve::resolve_effective_slots` is now the single resolver for `is_a` + mixin + `slot_usage` walks; previously this logic lived inside the Rust writer and was duplicated (in subtler, less complete forms) inside the HTML and graph writers. No behaviour change for any writer — the Rust writer's output is byte-identical, and resolution coverage that exists today continues to validate the same code via the new path. Future writer changes that need slot inheritance, mixin flattening, or `slot_usage` overlay call into one place instead of growing a fourth walker.
- **The schema graph layout default flipped from Force-directed to SGD.** SGD (Stochastic Gradient Descent variant of stress majorization) produces visibly cleaner cluster separation than force-directed on typical schema graphs at lower init cost than Kamada-Kawai or stress majorization. The manifest's `html_default_layout` still overrides, and existing user picker selections (stored in `localStorage`) still take precedence over both. In 3D mode the default falls back to Force-directed since SGD is 2D-only.
- **The schema graph view now defaults to 2D regardless of WebGPU availability.** Previously the renderer started in 3D mode whenever the browser supported WebGPU; in practice the 2D layout algorithms (Kamada-Kawai, Hierarchical, Stress, SGD) produce visibly better results than the WebGPU 3D force-directed path for typical schema graphs, and 2D is the mode the picker UX is tuned for. The 3D button stays selectable on WebGPU-capable browsers — users who prefer 3D switch with one click.

Surface changes addressed: `InstanceDescriptor` no longer `Default`, `Instance::new` takes the descriptor by value, `DeviceDescriptor` requires `experimental_features` + `trace`, `Adapter::request_device` is single-arg, `PipelineLayoutDescriptor` swapped `push_constant_ranges` for `immediate_size` and now takes `&[Option<&BindGroupLayout>]`, `RenderPipelineDescriptor.multiview` → `multiview_mask`, `RenderPassColorAttachment` requires `depth_slice`, `RenderPassDescriptor` requires `multiview_mask`, `DepthStencilState.depth_write_enabled`/`depth_compare` now `Option<_>`, `wgpu::Maintain` → `wgpu::PollType`, `Surface::get_current_texture` returns `CurrentSurfaceTexture` enum instead of `Result`.

### Fixed
- **A `key` or `identifier` set through `slot_usage` is no longer dropped, so a schema sharing one id slot across its record classes can split reference entities from per-dataset records.** The authoring rule is per-*class* — mark a class's id slot `key: true` when its records belong to their dataset, `identifier: true` when they are the same thing everywhere — but a schema that shares a single `id` slot across every record class, which is a natural LinkML shape, can only express that per-class distinction through `slot_usage`. The override was silently discarded during slot resolution: the resolver copied `identifier` and had never been taught about `key`, so the author saw a schema that said `key` and output that behaved like the base slot. Two consequences, both silent. Instance IRIs minted unscoped, so records that belong to their dataset denoted the same individual across datasets. And the Postgres DDL keyed the table on a synthetic `uuid` surrogate with a matching foreign-key column, instead of on the declared column — a different primary key and a different foreign key than the same schema produces when `key` is declared on the slot directly. Both now match the slot-level declaration exactly. Relatedly, the two uniqueness forms are mutually exclusive in LinkML — `identifier` is globally unique, `key` is unique within its container — so an override that sets one now clears the other; a slot left carrying both satisfied neither test and scoped nothing. Without this, such a schema had no way to split reference entities from scoped ones short of splitting the shared slot in two, which is a modeling change forced by the tool rather than by the domain.

- **The hazard scoping introduces is reported: one entity that two datasets each defined for themselves.** Once datasets scope apart, a shared record left defined in both no longer merges — it silently becomes two individuals, each dataset internally valid, and the cross-dataset collision check cannot see it because after scoping there is no collision left to find. `validate` (with repeated `--data`) and `publish` now report records that carry the same id and class in datasets that scope apart, naming the id, the class, and each dataset. Records whose **authored content differs** are deliberately not reported: two estates' `api-gateway` are different services sharing a generic name, and warning about those would fire on every separation scoping got right, drowning the signal. What is reported is therefore records that are *indistinguishable* — the message says "defined identically", which is both the basis it fired on and the thing to act on: add detail, or move the record to a shared dataset and reference it by CURIE. Like the collision report it is a note rather than an error, since only the author knows whether a split is intended.

- **One schema over many datasets stops silently merging them.** Every individual minted into the schema's namespace regardless of which dataset it came from, so two datasets that both used `id: api-gateway` became **one** individual the moment they were loaded together — the normal failure for a schema serving one dataset per tenant, lab, enterprise, or study. A dataset whose `tree_root` record bears an identifier is now a scope: its records mint beneath that root's IRI, so `acme/api-gateway` and `contoso/api-gateway` are distinct individuals, while the root itself stays the anchor rather than nesting inside its own scope. The scope is applied when the data is read and **never written back into the file**, so every already-authored dataset keeps working untouched. Scoping is off by default in the sense that matters: a root with no identifier is a vessel, not a scope-bearing entity, and its records mint exactly as before — which is why a teaching preview and the worked example it subsets are unaffected. Two datasets that *share* a root id share a scope, so a deliberately-overlapping curated pair keeps denoting the same individuals with no opt-out. Scoping applies uniformly to every class, with no global/scoped class designation anywhere: a record that must be shared across datasets lives in its own dataset and is named by CURIE (`id: catalog:aws`), which mints into the shared namespace and is left unscoped, so many datasets can reference one shared vocabulary record. Cross-dataset collision reporting and scoping now compose — two scoped datasets sharing a service name no longer report a collision, while genuinely shared records still do.

- **A schema can carry more than one `tree_root`, and each dataset is read against the one it conforms to.** A schema commonly needs both a scoped root and a shared reference root — an enterprise estate plus a provider catalogue, a sommelier's catalogue plus the grape/region vocabulary, a study plus a bibliography — because the classes the shared dataset holds are usually the model's hub, so splitting them into a second schema would mean duplicating or importing it. That was unauthorable: panschema took whichever `tree_root` sorted first and read *every* dataset against it, so a catalogue file read against an estate root produced a plausible, wrong, near-empty dataset with no complaint. The root is now chosen per dataset from the data's own top-level keys — the root declaring the most of them wins, which the disjoint collections these schemas actually have decide on the first key — and the choice is reported when a schema has several roots, so an author sees the reading they got instead of inferring it from the output. A file matching **no** root, or two equally well, is now a **violation naming the candidate roots** rather than a silent empty result that looks like a pass. Nothing is written into the data file and no manifest key is involved, so datasets stay portable and every already-authored file keeps working; a single-`tree_root` schema is unchanged, including the long-standing behaviour that a container key the root does not declare is skipped rather than fatal.

- **`validate` takes several `--data` files and reports the records they would silently merge.** One schema commonly serves many datasets — one per tenant, lab, enterprise, or study — and every individual mints into the schema's namespace, so two datasets that both use `id: api-gateway` become *one* individual the moment they are loaded together. Nothing detected that: identifier uniqueness is checked within a single file, and the command took exactly one file, so it never saw the pair. `--data` is now repeatable; each file is validated on its own (violation lines gain a file prefix once there is more than one) and the set is then checked for identifiers that mint to the same IRI across files, reporting the IRI, each file, and the id each used. The check keys on the **minted IRI rather than the id**, so a bare id and its CURIE form are recognised as the same individual — the pair that would otherwise slip through. `publish` runs the same check across its declared `[[instances]]` entries without being asked, since it already knows the full set. Overlap is reported rather than treated as an error: a teaching preview that is a strict subset of a worked example shares records deliberately, so the check states what overlaps and leaves the policy to the author. A single `--data` behaves exactly as before, down to the success and failure messages.

- **A reference into another graph is expressible instead of being an error or a dead string.** A class-ranged value written as an absolute IRI, or as a CURIE against a prefix the schema declares, is now read as an **external reference**: it emits as an IRI object in RDF — so another graph can join on it — is exempt from the dangling-reference error it previously tripped, and draws in the instance graph as a muted node outside the dataset, distinguishable at a glance from an intra-dataset edge. Because such a target cannot be checked here, `validate` and `generate` print a summary naming every one of them with its referring record and property, so an unresolvable target stays visible rather than passing as a silently unchecked link. A bare id is unaffected: it remains a promise about *this* dataset and is still dangling-checked, as is a CURIE against a prefix the schema never declared — far likelier a typo than an intended cross-graph link. The instance-graph legend's external row is retitled accordingly, covering both what it meant before (an upstream ontology category a class grounds into) and what it now also means (a record belonging to another dataset).

- **A `tree_root` container that is a real individual is no longer dropped from its own instance data.** A schema whose root class declares an `identifier` — a domain entity like an enterprise or a study, as opposed to a bare catalogue vessel — authored that record with an id and a name and got nothing: no `owl:NamedIndividual`, no graph node, no card, while every record it contained emitted normally. Such a root now emits like any other record, and its class-ranged collection slots draw references under their own predicate, so the RDF states which records it holds rather than leaving that to file structure. A container with no identifier still emits nothing, so a catalogue-shaped root gains no spurious node. Fixed alongside it: a root slot that leans on the schema's `default_range` rather than declaring its own — which an `identifier` typically does — was skipped entirely when reading the container, so such a slot reached neither the record nor the dataset metadata.
- **Enums reach the RDF output, and neither a union- nor an enum-ranged slot contradicts its own instance data any more.** A slot whose range is an `any_of` union of classes was declared `owl:DatatypeProperty` with no `rdfs:range` — a contradiction against an A-box asserting IRI objects — and now emits as an `owl:ObjectProperty` whose `rdfs:range` is a class expression closed by `owl:unionOf` over the members, so a consumer can see what the slot accepts. Enums were absent from RDF entirely: each now emits as an `owl:Class` closed by `owl:oneOf` over its permissible values, each value a labelled `owl:NamedIndividual` of that class carrying its description, with a value's `meaning:` CURIE supplying its IRI when given. An enum-ranged slot is consequently an object property over those value individuals, and takes the enum's class as its `rdfs:range` rather than emitting none. **Breaking for RDF consumers:** an individual's enum-valued assertion is now the value's IRI rather than a bare literal — `<…#color> <…#WineColorEnum/red>` where it was `<…#color> "red"` — so a SPARQL query matching those values as strings needs updating. A value the enum does not permit stays a literal rather than being invented as an IRI, and validation reports it as before. Enum and union list cells are addressable IRIs rather than blank nodes, matching how the SHACL shapes graph already writes `sh:or` lists.
- **A slot whose range is an `any_of` union of classes now carries references, not string literals.** Such a slot has no outer `range:` to read, so the instance reader fell through to the schema's `default_range` and ingested every value as a literal — the instance graph drew no edges for it, the RDF output asserted no object property, reference-integrity never fired, and the validator had nothing typed to check. Ingestion is now driven by each slot's induced range, so a union's members are visible whether declared on the slot or narrowed onto a subclass via `slot_usage` (including when the narrowing is itself a union). A union of classes makes string values references; a union mixing classes with types or enums keeps strings as scalars, since a string could legitimately be either; an inlined object becomes a record only when exactly one member is a class, and is reported rather than guessed when several are. On top of that, a reference at a union slot whose target is none of the permitted classes is now a violation naming them — a target whose class descends from a member through `is_a` conforms — while a target naming no record stays the integrity pass's single report rather than earning a second.
- **Inheritance no longer disappears when class names are unset.** The slot resolver's cycle guard keyed on a class's `name`, so any schema reaching it without names back-filled — every class holding the empty string — made each class look like a repeat of the last, silently truncating the `is_a` walk and dropping inherited slots, identifiers included. Classes are now distinguished by identity, so resolution is correct whatever the names say, and a genuine `is_a` cycle still terminates.
- **The instance graph offers the schema graph's inspection affordances.** It gains the hover detail card — an individual shows its classes, literal values, and IRI; a shared enum-value node names its enum and how many individuals chose it, a count that previously had no surface at all — plus the toolbar: reset and zoom buttons, and Labels, Nodes, Edges, Arrows, and Focus-on-hover toggles with the same persisted-preference behaviour as the schema canvas, re-applied whenever a dataset or layout switch re-creates the view. The controls are wired once through the shared shell serving both canvases. Five defects fixed along the way: the instance render loop never advanced the camera animation, so every camera fit — the settle-time fill, the reset button, resize re-fits — set a target the camera never reached; the legend button never showed its pressed state; nodes couldn't be dragged — the canvas's mouse handling was hard-wired to pan, so grabbing a node now moves that node while grabbing empty space still pans, as on the schema canvas; clicking a node didn't keep its card — a click now selects the node and pins its card open until empty space is clicked to deselect, matching the schema canvas; and that selection was then flaky in the hand, because any pointer movement at all counted as a drag, so the pixel or two a trackpad click wanders suppressed it — the card wouldn't pin, the node was nudged instead, and clicking away wouldn't clear. Click-versus-drag discrimination and Escape-to-deselect now come from the shared page shell, measured from where the press began rather than between consecutive moves, so the two canvases can't diverge on it again and a slow drag of small steps registers as the drag it is. The `enum_value` metadata tag is spelled consistently with the node type on the wire.
- **The instance graph is typed: each schema node type expands into its instances, drawn with that type's own symbol.** Every individual used to render as one generic teal marker regardless of its class, and an enum-valued slot was a card literal only. An individual now wears its class's circle and colour, and each enum value actually in use becomes one shared diamond node — coloured like its enum, carrying its usage count — that every choosing individual links to with a slot-labelled edge, so "which individuals share this value" reads as graph structure. Scalar literals stay on the card rather than becoming leaf nodes, and assertions remain plain directed arrows: cardinality decorations are schema-graph-only, since an assertion is one concrete fact. The entity list also tags each individual with its class, so two individuals of different classes sharing a display name read apart. This is a wire-format addition (`format_version` 1.2, a new `enum_value` node kind) mirrored in the visualization; pre-1.2 documents parse unchanged and individual IRIs are untouched.
- **Each graph's notation key is adaptive, and the instance graph finally has one.** The legend was a fixed table drawn identically everywhere: it advertised symbols a schema might not use (the enum diamond on an enum-free schema), had no entry at all for the two things an instance graph draws — individuals and assertion edges — and didn't exist on the instance canvas. The key now lists only the node, edge, cardinality, and ring rows the graph in front of it actually contains, computed from the same tables the renderer draws with and exposed as a queryable summary so tests assert the drawn key rather than pixels. The panel sizes to its rows — the key's extent comes from the same metrics the drawing uses, so a short key no longer sits in a tall fixed box of dead space. The instance graph gains a Legend toggle; the standalone full key remains for previews with no graph to inspect. Behind this, the page-side wiring both canvases share — settle-and-refit, hover-focus, badge formatting, layout persistence, resize forwarding, legend rendering — moved into one module, so the two graph shells can no longer drift apart.
- **The instance graph is now explorable like the schema graph.** Its canvas initialized a reduced view of a renderer that is already generic: the layout settled without the camera ever fitting it, so nodes clustered in one corner of a large empty box; there was no layout picker and no focus-on-hover; and window resizes updated the canvas without telling the visualization, leaving hit-testing and camera fit against stale dimensions. The instance canvas now re-fits the camera at the same settling checkpoints the schema graph uses, offers the same layout picker (persisted under its own key, since a good instance-graph layout can differ from the schema's), focuses the hovered node's neighborhood at the same hop depth, and forwards resizes. A layout change or dataset switch re-creates the view with the chosen settings.
- **Graph counts read `nodes / edges` everywhere, and the instance heading no longer shows an individual count.** Three formats described the same idea: the schema-graph heading spelled out `37 nodes, 60 edges`, its sidebar entry said `37 / 60`, and the instance-graph heading showed a bare `28` — which looked like a node count but was the number of individuals, silently omitting edges. Every graph count — sidebar entry, section heading, and each instance-graph selector button — now reads `nodes / edges` and carries the spelled-out reading as a tooltip and accessible name. With several curated instance graphs, the heading *and* the sidebar entry follow the selected dataset — leaving the sidebar on its landing value had two badges disagreeing about one graph — while each button keeps its own dataset's numbers. List sections keep their single count: a list has one dimension, a graph has two.
- **Curated instance graphs sharing record ids collided on the page.** A teaching preview is usually a subset of the worked example, so the same individuals appear in both panels — which emitted duplicate element ids and sent a reference link in one panel to the *other* panel's card, hidden, so the link looked dead. Each dataset now has its own anchor namespace. A page with one instance graph is unchanged, keeping its published `#ind-<id>` deep links working.
- **A custom type's `typeof` parent is no longer silently dropped.** A `types:` entry declaring `typeof: <parent>` (LinkML's type-inheritance slot) parsed to nothing — the field was matched under a non-standard `typeof_` key, so a real schema's `typeof` was ignored and the type's base was lost everywhere it's used (the docs' "Subtype of" row, the schema graph's type-inheritance edge, and now the JSON-Schema writer's base-type resolution). The field is read from the correct `typeof` key now, so custom type inheritance survives the read. (panschema's own fixtures had used the non-standard `typeof_` spelling, which masked the bug; they're corrected to `typeof`.)
- **OWL/Turtle output now declares the standard `xsd:`/`rdf:`/`rdfs:`/`owl:` prefixes it uses.** A datatype range like `integer` emitted `rdfs:range` with a verbose absolute `http://www.w3.org/2001/XMLSchema#integer` IRI because the OWL writer's prefix map carried only the schema's own `prefixes:` block, never the built-ins the graph itself emits. Both Turtle-emitting writers (OWL and SHACL) now build their prefix map through one shared helper that layers each writer's built-in prefixes on the schema's, so `xsd:`-typed terms serialize in compact form.
- **`generate --output new/dir/out.<ext>` now creates missing parent directories for every format.** Only the Rust and Postgres writers created the output's parent directory; the OWL/Turtle, JSON-LD, RDF/XML, N-Triples, graph-JSON, and SHACL writers called `File::create`/`fs::write` straight away and failed with "No such file or directory" when the target directory didn't exist. All file-producing writers now go through one shared `ensure_output_parent` helper, so the behavior is uniform across formats.
- **SHACL rule shapes are now correct for integer equality, unknown slots, and one-sided rules.** Three fixes to the conditional `rules` → SHACL projection: (1) an `equals_number` check on an integer-range slot emitted a `sh:hasValue "N"^^xsd:double` literal, but `sh:hasValue` is datatype-sensitive term equality and the instance data is `xsd:integer`, so the literal could never match — silently inverting the rule; the literal is now typed to the slot's range (`xsd:integer` for integer ranges). (2) A rule condition naming a slot the class doesn't have previously fabricated a `{ontology}#{slot}` property IRI and emitted a shape that rejected all valid data; such a rule (and a one-sided or empty-conditioned rule) is now skipped, with a `generate --format shacl` warning naming it — matching how the Postgres writer already reports unrepresentable rules. (3) A shared skip-reason check keeps the writer's emission and the warning in agreement.
- **Generated Rust ends with a single terminating newline.** The writer previously emitted a trailing *blank* line (`}\n\n`), which EOF-normalizing pre-commit hooks rewrite and which would defeat a regenerate-and-`git diff` drift check (a fresh generation never matched the normalized committed file). Output now ends in exactly one `\n`, so it commits verbatim and diffs cleanly.
- **OWL/Turtle reader now reads `owl:deprecated`, `skos:altLabel`, `rdfs:seeAlso`, the SKOS mapping predicates, and OWL property characteristics back into the IR.** The writer already emitted these for deprecated, aliased, cross-referenced, mapped, and characteristic-bearing classes and slots, but the reader never parsed them — so a Turtle → IR → Turtle round-trip silently dropped every one of them. The reader now reads `owl:deprecated true` into the `deprecated` flag, `skos:altLabel` into `aliases`, `rdfs:seeAlso` into `see_also`, `skos:exactMatch`/`closeMatch`/`relatedMatch`/`narrowMatch`/`broadMatch` into the matching `*_mappings`, and `owl:SymmetricProperty`/`AsymmetricProperty`/`ReflexiveProperty`/`IrreflexiveProperty`/`TransitiveProperty` into the corresponding characteristic flags — so these constructs survive a Turtle round-trip instead of vanishing on read-back. (RDF carries only the deprecation boolean, so the migration-note text isn't recovered, but the deprecated state is.)
- **Generated Rust code now escapes reserved keywords — including type names.** A schema with a name landing on a Rust keyword — an enum permissible value like `virtual`, a slot named `type` or `move`, or a class or enum *named* `type` or `move` — previously emitted the bare keyword, producing code that didn't compile (`error: expected identifier, found reserved keyword`). This now covers every emission site: enum variants, struct fields, constructor parameters, and the struct / enum / trait type names themselves (a class named `move` becomes `pub struct r#move`, referenced as `r#move` everywhere it appears — field types, `Box<…>` inners, trait bounds, and `impl` targets). Keyword idents are emitted as raw identifiers (`r#type`, `r#virtual`); the handful that are illegal even as raw identifiers (`crate`, `self`, `Self`, `super`, `_`) get a trailing-underscore mangle instead (`self` → `self_`). An escaped field or variant keeps its original wire name via a `#[serde(rename = "…")]` so JSON round-trips unchanged; type names aren't serialized, so they need no rename. Separately from keywords, a name that cannot become a Rust identifier at all (spaces, punctuation, a leading digit) now fails the write with an error naming the offender — previously it was emitted verbatim, producing code that didn't compile or, for a hostile schema, injected arbitrary tokens into the generated source.
- **Per-class `slot_usage` range narrowing now shows on the class card and in the graph.** A class that narrows an inherited slot via `slot_usage` — a single `range`, a smaller `any_of`, or `maximum_cardinality: 0` — previously showed the wide *inherited* union everywhere (the scalar-range-over-`any_of` case left both populated, so the union masked the narrowing), hiding the per-class shape. The class card now renders the induced range — a scalar narrows to that one range, a smaller union replaces the inherited one, and a slot suppressed by `maximum_cardinality: 0` reads as "has no value" — and the schema graph draws range edges from the narrowing class directly to its induced targets (and none for a suppressed slot), so a class connects to exactly the artifacts it actually takes and produces instead of the whole envelope. Computed once in the shared resolver (`InducedRange`) so every writer consumes the same per-class view.
- **Polymorphic `any_of` ranges are no longer dropped.** A slot whose range is an `any_of` union (e.g. an input that may be a `Dataset`, `Question`, or `Result`) now draws a graph range edge to every member and lists the whole union on its slot card. Previously the range vanished — the member classes appeared disconnected in the graph and the card's Range row was blank.
- **Graph node detail cards label slot nodes correctly.** A slot node's hover/detail card now reads `Type: Slot` (and `Enum` / `Type` for those kinds) instead of `Class`. The label is read from the node's kind, not inferred from a color channel that collided between the class and slot palettes.
- **External `subclass_of` grounding now round-trips through the IR, HTML, and RDF.** LinkML's `subclass_of:` field — used to declare `rdfs:subClassOf` to upstream ontology classes (BFO, CCO, IAO) distinct from intra-schema `is_a` — previously parsed and then vanished: no IR field existed, the HTML showed nothing, and the emitted RDF was missing the grounding axioms the schema declared. The class card now renders a "Subclass of (external)" row with CURIE-expanded hyperlinks (and a muted-text fallback for unrecognised prefixes), and the RDF serializers emit one `rdfs:subClassOf <expanded>` triple per entry.
- **`class_uri` and `slot_uri` in the HTML class and slot cards are now CURIE-expanded hyperlinks.** Previously these rendered as plain `<code>` text, so a `class_uri: cco:ont00000005` was visible but not clickable, and a CURIE-only entry like `cco:ont00000005` displayed the abbreviated form with no path to the upstream definition. The cards now wrap the displayed text in `<a href="…">` pointing at the expanded IRI (resolved against the schema's `prefixes:` table), and the existing copy-IRI button copies the expanded form so a paste yields a directly-resolvable URL. CURIEs whose prefix isn't declared fall back to plain text, unchanged.
- **Cross-ontology mappings now round-trip through the IR, HTML, and RDF.** `exact_mappings`, `close_mappings`, `related_mappings`, `narrow_mappings`, and `broad_mappings` on classes and slots previously parsed and then vanished — the YAML accepted the keys but no field existed on the IR, so the grounding values authors wrote (BFO / CCO / CiTO / IAO IRIs) silently dropped from every output. The five fields are now first-class IR fields; HTML class and slot cards render a "Mappings" row with the mapping kind and a CURIE-expanded hyperlink (falling back to a muted-text indicator when the prefix isn't declared); the RDF serializers emit one triple per mapping under the matching SKOS predicate (`skos:exactMatch`, `closeMatch`, `relatedMatch`, `narrowMatch`, `broadMatch`).
- **Schema graph hover card now surfaces `slot_usage`-introduced slots.** Class-node hover previously walked `is_a` + mixins + `attributes:` + `slots:` but missed slots that a subclass added or refined via `slot_usage`. Now goes through the shared resolver, so e.g. `Question` (extending `Activity`) shows the `wasGeneratedBy` slot it refines via `slot_usage` even though the slot was inherited.
- **Static graph layouts (Kamada-Kawai, Hierarchical, Stress majorization) now survive node selection and single-node drag.** The drag handler in the visualization reheated the simulation unconditionally on every mousedown that hit a node — including click-without-drag — which re-enabled the per-tick force-directed physics. The result: any click on a KK / Sugiyama / Stress page sent the layout into force-directed motion, undoing the static algorithm's work. Static layouts now skip the reheat on drag, so a single-node drag moves only that node and the rest of the layout stays where the static algorithm placed it.
- **Graph viz no longer drops slots referenced only via `class.slots:`.** The graph builder previously emitted class↔slot edges only from the slot-side `domain:` field, so slots listed by a class but missing `domain:` rendered as orphan nodes — even though the HTML class card already drew the connection correctly. The builder now also walks each class's `slots:` list and emits the equivalent edge, deduping against the slot-side pass so a slot with both `slot.domain = C` and `C.slots: [s]` produces one edge, not two. LinkML treats `domain` and `domain_of` as the same relation; the graph now matches.
- **Schema-level description in the metadata card is no longer double-escaped.** The metadata card template mounted `comment` without `|safe`, but the writer pre-renders that value as HTML (through `render_description`) — so Askama escaped the writer's `<p>…<a href="…">…</a>…` markup a second time and authors saw literal `<p>…</p>` markup as visible text. The fix is `{{ comment|safe }}`, matching the entity-card descriptions.
- **Header brand link in rendered HTML is no longer an absolute `/`.** Each page's `<a class="site-title">` previously emitted `href="/"`, which resolved to the *domain root* on subpath deploys (e.g. clicking the brand on `https://<user>.github.io/<repo>/schema/main/` sent the user to `https://<user>.github.io/`, 404 for the project). `panschema generate` now emits `./` (the page lives at the output root, so `./` is the deploy root). `panschema publish` reads the target from a new manifest field `[publishing].site_root_url`, default `"../current/"` — parent-relative to the canonical current-version page within the publish output cohort, symmetric with `url_pattern`'s `"../{version}/"` default. The default works for any standalone publish deploy; consumers whose publish dir is nested under a parent site (e.g. `<book>/schema/<version>/`) override the field (e.g. `"../../"` to escape into the book).
- **Schema graph 2D layout now uses the full configured aspect-ratio viewport and produces legible labels at all graph sizes.** The CPU force simulation gains three composable changes: (1) anisotropic axial centering (`forceX` / `forceY` with `gravity_y / gravity_x = (w/h)³`) so isolated nodes equilibrate at a radius matching the configured aspect — landscape containers no longer leave half the horizontal space empty; (2) the largest connected component is placed at origin so anisotropic gravity doesn't have to fight an off-center initial layout; (3) `link_distance`, `charge`, and `collide_padding` scale with `√N` so the same defaults produce visibly-legible layouts from 6-node fixtures up to 100-node ontologies — the collide-padding scaling matters most, since collide is the only force that enforces minimum geometric spacing between every node pair. Validated via a multi-scale Playwright iteration test (`#[ignore]`-d for routine CI) that screenshots a synthetic graph at phone (390×844), laptop (1440×900), and 4K (3840×2160) viewports.
- **RDF serializers (TTL / JSON-LD / N-Triples / RDF/XML) now expand CURIE-shaped IRIs against the schema's `prefixes:` table** before emission. Previously a `class_uri: cco:ont00000005` produced `<cco:ont00000005>` — invalid as N-Triples (the spec requires absolute IRIs in `<...>`) and ambiguous in TTL/JSON-LD/RDF/XML (parsers read it as a relative IRI against the empty base). The TTL writer now also wires sophia's `TurtleConfig::with_prefix_map` so the schema's prefixes round-trip into `PREFIX` declarations at the top of the output. JSON-LD and RDF/XML emit fully-expanded absolute IRIs.
- **LinkML mixins now emit `rdfs:subClassOf` alongside the `is_a` parent in OWL output.** LinkML treats `mixins:` as multiple inheritance; the prior emitter only honored `is_a`, so a class declaring three mixins lost three subClassOf relations from its RDF representation.
- **RDF/OWL output now declares properties for inline `attributes:` and inherited/mixed-in slots.** The RDF family (TTL, JSON-LD, RDF/XML, N-Triples) walked only top-level `slots:`, so a class written in the idiomatic inline `attributes:` form — or one whose slots come via `is_a`/mixins — emitted as a bare `owl:Class` with none of its properties declared, and any SHACL `sh:path` pointing at those properties had no OWL counterpart. The writer now resolves each class's effective slots (the same resolution the HTML, Rust, Postgres, and SHACL writers already share), declaring every attribute/effective slot as a property with its type, label, and range plus an `rdfs:domain` naming the owning class — deduped so a slot that is both top-level and effective emits once.
- **RDF/OWL now expands a bare (colon-less) name against the schema's `default_prefix`, consistent with the HTML output.** CURIE expansion is now a single shared implementation used by the RDF builders and the HTML writer, so a `class_uri`/`slot_uri` written as a bare name resolves the same way in every format instead of the RDF writer leaving it unexpanded.
- **Range aliases (`int`/`bool`/`str`) map to the same type across every writer, and no writer fabricates an `xsd:` IRI for a non-primitive range.** A shared primitive table now backs the RDF/OWL, SHACL, Postgres, and Rust type mappings: a range written `int` emits `xsd:integer` (not a nonexistent `xsd:int`), and a range that names no class, enum, `types:` entry, or built-in primitive — a typo, already flagged by the dangling-reference diagnostic — emits no `rdfs:range`/`sh:datatype` at all instead of a fabricated `xsd:{name}`. This generalizes the earlier enum-range fix to every non-primitive range.
- **OWL/RDF output no longer fabricates a nonexistent `xsd:` datatype for an enum-ranged slot.** A slot whose range is an enum is neither an object property nor an XSD scalar, but the range emitter fell through to the scalar mapping and produced `rdfs:range xsd:{EnumName}` — a datatype that does not exist. Enums have no RDF projection yet, so such a slot now emits no `rdfs:range` at all (guarded the way the SHACL and Postgres writers already handle enum ranges) instead of a dangling reference to a made-up datatype.
- `YamlReader` now infers metaobject names from their dict keys (idiomatic LinkML), so explicit `name:` and permissible-value `text:` fields are optional. Applies to classes, slots, enums, types, class attributes, class slot_usage, and permissible values. Schemas produced by `linkml-runtime` and the broader LinkML toolchain (`gen-owl`, `gen-shacl`, `gen-python`) now load without modification. Explicit names still work; an explicit name that disagrees with the dict key is now a clear parse error.
- `GraphWriter` now emits range edges for inline class attributes (e.g., `Student.year` → `YearEnum`). Previously only top-level `slots:` produced domain/range edges, so most relationships in idiomatic LinkML schemas were silently dropped from the visualization. Inline attributes connect the owning class directly to the range target (no separate slot node), labeled with the attribute name.
- 3D camera `zoom()` direction was inverted relative to the 2D camera and the documented contract; `factor > 1.0` now zooms in for both.

### Security
- **Generated HTML docs no longer let schema content break out of the embedded graph JSON (stored XSS).** The interactive graph's data is embedded in an inline `<script>` as JSON, and JSON does not escape `<` — so a `</script>` inside any schema string (a class/slot name or `description`) closed the script element mid-JSON and executed whatever markup followed, in the browser of anyone viewing the generated (or published) docs. Every `<` in the embedded JSON is now escaped as `<`, which `JSON.parse` decodes back to `<` — the graph data is byte-for-byte unchanged, only the on-page representation is safe. Affected anyone rendering docs from a schema they did not author.
- **The dev server (`panschema serve`) now binds loopback (`127.0.0.1`) by default instead of all interfaces (`0.0.0.0`).** It previously exposed the generated docs to the entire local network while printing a `http://localhost:…` URL that hid the exposure. Pass `--host-all` to opt back into binding all interfaces.
- **`imports:` can no longer escape the schema's directory tree.** A relative import such as `../../../etc/passwd` was resolved and merged like any local file; a fetched, untrusted schema package could use it to pull arbitrary host files into a consumer's generated output. Every import (transitively) must now resolve within the root schema's own directory tree, canonicalized so `..` escapes are caught by where they actually point — an out-of-tree import is a hard error naming the offending entry.

## [0.2.0] - 2026-01-25

Project renamed from **rontodoc** to **panschema** to reflect broader schema support.

### Added
- **LinkML Internal Representation (IR)**: Canonical data model based on LinkML metamodel
- **Reader/Writer Architecture**: Extensible pipeline for multi-format support
- `OwlReader`: Parses OWL/Turtle to LinkML IR
- `HtmlWriter`: Generates HTML documentation from LinkML IR
- Support for OWL individuals with type links and property values

### Changed
- **BREAKING**: Binary renamed from `rontodoc` to `panschema`
- **BREAKING**: Crate renamed from `rontodoc` to `panschema`
- Internal architecture refactored to use Reader → IR → Writer pipeline
- Classes map to LinkML `ClassDefinition` with hierarchy preserved
- Properties map to LinkML `SlotDefinition` with domain/range
- XSD datatypes mapped to LinkML built-in types

### Removed
- Old monolithic parser and renderer (replaced by Reader/Writer architecture)

## [0.1.0] - 2026-01-24

Initial release of rontodoc — a fast, single-binary ontology documentation generator.

### Added
- CLI with `generate` and `serve` subcommands.
- Turtle (.ttl) parser for OWL ontologies: classes, properties, individuals, and metadata.
- Class cards with labels, descriptions, IRIs, and class hierarchy (superclass/subclass links).
- Property cards with type badges, domain/range, and inverse-of relationships.
- Individual cards with type links and property values.
- Sidebar navigation with section links and count badges.
